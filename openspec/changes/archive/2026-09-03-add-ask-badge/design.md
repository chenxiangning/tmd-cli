## Context

add-ask-sound 世代,Ask 检测(标记正则 + ANSI 剥离 + 跨分片尾巴 + 页脚窗口)以
`ipc.onPtyOutput` 第二观察者形态自持在 askSound.ts,刻意让 host 零感知 —— 动机是
「热点文件 host.ts 不增一行」(见 add-ask-sound/design.md 决策 1/5)。

本变更需要把「等待确认」变成 UI 可读的会话状态:标签是首类 UI 状态而非锦上添花的
声音,状态必须挂在 host 上让列表同步渲染。彼时的约束已松动:outputBuffers 拆分后
host.ts 有行数余量,ActivityWatch 已确立「host 组合状态仓 + 回调」模式,500 行铁则
靠组合而非绕行满足。

## Goals / Non-Goals

**Goals:**

- 提问/确认面板出现时,对应会话行立即亮「等待确认」标签;作答立即清除
- 检测单点化:标签与提示音共享同一检测,不双份正则各自漂移
- host.ts 保持 ≤500 行(铁则),askSound 保持纯音频职责

**Non-Goals:**

- 不给等待会话做置顶排序(完成未读置顶已覆盖"需要关注";等待与未读高度共现)
- 不做标签设置开关(零打扰成本:不响不弹,只是状态呈现)
- 不在标签页栏/其他会话呈现面打标(列表是会话状态的唯一权威面)
- 不解决「CLI 自行继续(超时/自动确认)后标签残留」——标记集只认真实面板字面量,
  自行继续的 CLI 必然重绘掉面板,残留属误报同一类,由页脚窗口收敛

## Decisions

1. **检测上收 host 主链路**:`AskWatch` 状态仓进 `host.appendOutput`(唯一拥有原始
   输出文本的汇聚点),替代 askSound 的每会话第二 `onPtyOutput` 订阅 —— 检测点从
   2 处归 1,每会话输出监听器减半,且天然继承存活守卫(退订前迟到输出不得复活已删
   会话状态)。host 发 `askDetected` 事件供提示音消费,与 `turnSettled` → turnSound
   同构;UI 走 `host.isWaitingConfirm` 只读。
2. **状态语义 = 边沿,不是时间窗**:置位(未等待 → 标记命中)/ 清除(用户写入 /
   会话移除)。旧时间窗去重被替代:一个未回答的提问期间无论 TUI 重绘多少次只触发
   一次;作答后的下一个提问(含连续多问流程)各自触发 —— 旧行为里 2s 内连续两问
   只响第一声,新语义修正。等待期间**不因新输出清除**:挂起面板的 CLI 仍在持续重绘
   (spinner/token 计数),输出流不能作为"已不再等待"的信号。
3. **作答时尾巴一并重置**:`onUserWrite` 清等待 + 清 240 字符尾巴 —— 否则旧提问
   字面量停留在尾巴里,写入回显的短 chunk 拼接后仍落在页脚窗口内,标签瞬间复燃。
4. **host 组合遵循 ActivityWatch/OutputBufferStore 模式**:字段 + appendOutput/
   writeSession/removeSession 三挂点 + isWaitingConfirm 只读,host.ts 净增 8 行
   (491 → 499),铁则内。
5. **UI 双呈现面**:CLI 分组活会话行(meta 区,pin 角标之前)与全局置顶区的活绑定行
   (同 `.thread-ask-badge`);磁盘历史行无 PTY,不打标。色板锚定呼吸灯绿
   `#34d399`(soft 底 + 描边,与 welcome-pill 同构),不随主题漂移。
6. **askSound 保持播放管线与设置门控不变**:`playAskSound`/`resolveAskSoundId`/
   懒加载缓存原样;boot 改订阅 askDetected,幂等(重复 boot 复用退订句柄)。

## Risks / Trade-offs

- **作答残影误置**:作答后最初几帧重绘若仍含面板字面量且落在页脚窗口,标签会重置。
  缓解:页脚窗口(末 5 行)+ 作答尾巴重置已把窗口压到最小;与提示音同误报面,
  出现率与标记集保守度同阶,可接受。
- **宽限/回放期间命中**:打开停 在提问上的历史会话,resume 回放重现面板 → 标签亮
  (提示音同响)。这是正确语义:该会话确实在等确认,不是误报。
- **检测上收是行为变更点**:提示音从「每轮至多一次」变「每段等待一次」。规格场景
  (重绘不重复、作答后再响)全部保持成立;极端差异(长时间挂起重绘不重复提醒)是
  改善而非退化 —— 持续视觉标签已接管"还在等"的提醒职责。
