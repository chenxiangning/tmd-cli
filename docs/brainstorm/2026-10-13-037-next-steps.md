## 二、0.3.7 待办指引

### 批次零:门禁红必须先解(本次实测新增)

**现状**:2026-10-13 12:03 在本机跑 `pnpm check:gate`,**红**,唯一失败项:

```
FAIL  src/mobile/engines.test.ts > 手机引擎表与桌面插件 profile 对齐 > omp: command/resume/bracketedPaste 一致
Error: Test timed out in 30000ms.
Test Files 1 failed | 502 passed (503)
Tests      1 failed | 3926 passed (3927)
```

- **可复现**:单跑该文件同样失败(`1 failed | 10 passed`,耗时 38s);同文件其余 10 个引擎用例全过(dsh 仅 949ms)。
- **根因**:该用例是文件内第一个,吃掉 `cli-omp/index.tsx` 全模块图的冷变换(React 组件 + `academy/academyCatalog` + phosphor 图标 + market/providerAuth),已超出用例硬编码的 `30_000` 预算(文件头注释已自述「本机可超 vitest 默认 5s」,当时提到 30s,现又不够)。
- **与 0.3.7 无关**:`git diff main..Tmd-0.3.7` 未触碰 `src/mobile/` 与 `src/plugins/cli-omp/`,该测试最后改动停在 0.3.1 的 `a96412b4`;属机器负载敏感的历史欠账,恰好在本轮收口时暴露。
- **注意**:CLI 传 `--testTimeout=240000` 无效——用例第三参显式传了 `30_000`,优先级高于 CLI/config。
- **建议修法(根因,最小 diff)**:在 `describe` 内加模块级预热,把冷变换移出用例预算:

  ```ts
  import { beforeAll, describe, expect, it } from "vitest";
  // ...
  beforeAll(async () => { await Promise.all(Object.values(PLUGINS).map((f) => f())); }, 300_000);
  ```

  预热后每个用例命中模块缓存即秒过;若嫌重,退一步只把 omp 那一例的预算提到 `120_000`。
- **连带影响**:四批提交的「提交前终态 check:gate 全链绿」是 03:19 的实测结论,当时为真;现本机已不成立,**推送前必须在新树上复验**(AGENTS.md 已立的规矩),不要凭旧结论直接推。
