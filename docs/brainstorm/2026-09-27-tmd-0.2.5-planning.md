### 任务三:异常退出卡接跨引擎接力(一天)

gap-analysis P1-3 的落地切片:崩溃恢复路径从「只能原引擎续聊」扩到「可换引擎接力」。**决策:不做「疑似额度」退出嗅探**——CLI 撞墙多数不退出而在幕布报错,退出码无额度语义,嗅探 = 猜测兜底,违反「不做猜测」纪律;接力按钮直接补动作缺口,不赌分类。

- 现状件:`ExitSessionToast.tsx` 异常退出卡已有「一键续聊」;`session-relay/relayStore.ts` 的 `setRelaySource` 是现成开框原语;`RelayDialog` 的摘要走 `readSessionUserMessages` 读磁盘——**会话已退出也能读到**,链路天然成立。
- 改动面:
  1. `ExitSessionToast` NoticeCard:在「一键续聊」旁加「转其他引擎接力」按钮,条件同 `canResume`(kind=cli 且 cliSessionId 在);点击 = 用退出详情快照组 `RelaySource`(profileId/cliSessionId/cwd/title)→ `setRelaySource` 开对话框。源构造逻辑从 `session-relay/index.tsx:39-46` 命令处理器抽共享(一处组源,两消费方)。
  2. import 方向:app-shell → `@plugins/session-relay` 的 store(plugins/index.ts 既有 app-shell 聚合插件先例,方向合法;不反向)。
  3. 词典:按钮文案 ×3 语(按钮/已有复用)。
- 验收:新增退出卡呈现测试断言按钮条件(复用 ExitSessionToast 既有测试模式);桩目检:桩杀一个 CLI 会话 → 退出卡双按钮 → 接力开框显示已退出会话的摘要。
- 风险:中低。注意 `SessionExitedDetailEvent` 快照字段齐全度(title 可能缺,`RelaySource.title` 本就可选)。

## 方案取舍(本规划层面的决定)

| 决定 | 选定 | 否决与理由 |
|---|---|---|
| 0.2.5 主轴 | 验收收口 + 摩擦清零 | 再开大功能:冲突雷达/战略题没有收敛过的设计,挤占验收会拖长未闭环项 |
| 失败分类深度 | 只补「退出 → 接力」动作面 | 「疑似额度」退出嗅探:退出码无额度语义,撞墙多数不退出;猜测分类 = 假信号,宁漏勿扰纪律 |
| 拒绝引导形态 | 文案引导 + 直达聚焦幕布 | 代发拒绝键/自造允许拒绝按钮:各 CLI 键位语义不一,发错键 = 批错操作(M2 评审 A2 已裁) |
| vitest/russh 升级 | 单验不并批 | 并批:大版本与主链组件混在一起,红了无法二分归因 |
| 签名 | 随 0.2.5 可选启用 | 强绑发版:采购与 secrets 是用户侧时间,不应阻塞版本节奏 |
| russh 真连 | 来不及则推 0.2.6 | 只信 `cargo test` 放行:SSH 是一等会话,回归必须真连 |
