# 调研:工作台「项目列表 / 时间线 / 待跟进」三视图重构

- 日期:2026-10-12
- 状态:调研完成,方案待大仙定夺(未开发)
- 需求来源:大仙——三视图展示的业务数据不知道解决什么问题,疑似无效设计、收益低;本篇调研结论先行,给出合并或按真实工作场景重构的方案取舍

## 结论(先行)

1. **三视图是 projectHub(PM 报表工具)的移植遗产**,与 tmd-cli 的真实场景(单人 + AI 会话干活)双重错位:数据错位 + 场景错位,不是实现质量问题,是视图要回答的问题没人问。
2. **数据事实(本机真实数据量化)**:16 个项目里 13 个是「一键关联工作区」批量导入的空壳(含 `.ssh`、`home`、`Downloads`);有任务的项目 3 个(共 6 条任务)、有截止日 2 个、有开始日 1 个;模块轴 16/16 全是「其他项目」、负责人轴 16/16 全是「我」、进度 14/16 = 0%——项目列表的 9 列里 5 列、时间线的全部日期前提、概览的模块/负责人负载图,都建在死轴上。
3. **场景事实**:时间线的残余价值(到期展望)已被「日历并入工作日志月视图」接收(commit 052be5a1,日格叠项目 DDL 与未完任务);待跟进 = 任务看板的到期排序平面投影(任务看板 2026-10-12 刚五态化,泳道/拖拽/内嵌详情全覆盖);项目列表是有报表皮没索引能力的孤页(无搜索/排序/行内操作,唯一交互是点名字开详情)。
4. **推荐方案 A:三页签全撤,合一个「聚焦」页签;项目索引并入概览底部**。页签 7 → 5(概览 / 聚焦 / 任务看板 / 文档 / 工作日志)。详见「方案取舍」。

## 现状盘点(代码事实)

对照组(已 strong 的邻面):任务看板 = 项目泳道 × 状态列,整卡拖拽改态 + 内嵌任务详情 + 就地推进;概览 = KPI + 一句话结论 + 风险环形/模块负载/进度直方/负责人负载 + 「需要马上处理」+「本周到期」;日志月视图 = 日格热力 + 项目 DDL + 未完任务条目。

深链与外部消费(grep 全仓实证):三页签仅 `wbTabs.ts` + `WbScreen.tsx` 两处引用;工作台对外深链只有 `tab: "docs"`(`openWorkbenchDocsTab`),list/timeline/followups 无任何深链消费方;`wb.console / wb.project` tab kind 不受页签增删影响。

派生函数消费面:`calendarTimeline.ts` 被日志月视图复用(`calendarMonth` + `CalendarItem`,`JournalTab/MonthView` 在用)——**该文件必须保留**,只 orphan `timelineModel` 入口;`followUpBuckets.ts` 被 Followups + 纯函数测试消费,可直接喂新视图;`analysis.ts / insights.ts` 同时供概览/问一句/文档生成使用,与三视图解耦。

## 逐视图诊断

### 项目列表:是报表皮,不是索引工具

- 它回答的问题(「全部项目的字段总览」)是 PM 周报问题;单人场景的真实问题是「找到那个项目,打开它」——需要的是搜索、活跃度排序、快速开详情/开会话,而这三样它都没有。
- 9 列中 5 列(模块/负责人/进度/剩余/风险)在真实数据里近乎全空或恒定,表格 = 一屏「—」和「我」。
- 与邻面重叠:风险/到期汇总概览已有,任务数任务看板已有,字段编辑在项目详情 tab。独立页签的独占价值为零。

### 时间线:前提(项目级起止日期被认真维护)不成立

- 甘特图的核心价值是排程冲突与依赖关键路径,都是多人团队工具的语义;单人多项目场景退化为「什么时候到期」——这已被日志月视图日格(叠 DDL 与任务条目,`052be5a1`)和概览「本周到期」覆盖。
- 数据面 3/16 有日期。要求用户为 16 个目录手工维护起止日期,维护成本 > 收益,死视图是必然结局。
- 保留条件不存在:没有"拖动横条改排期"的编辑能力,它是画出来的报表,不是工具。

### 待跟进:数据没死,但它是别人的投影

- 五桶里真正会看的只有前三桶(逾期/今天/本周),与概览「需要马上处理 + 本周到期」、任务看板按截止排序列三处答同一个问题。
- 任务看板五态化后,任务的一切操作(推进/详情/拖拽)都在看板;待跟进是看板的只读切片 + 到期排序,独立页签的增量 = 一个排序视角,撑不起一页签。

### 共同根因

三视图消费的都是**手工维护字段**(日期/进度/模块/负责人),而本工具的真实数据面是**自动可得的活动流**:会话(`Project.cwd` 绑定 + `TaskSessionLink`)、日志(日会话摘录)、任务时间戳(`startedOn/doneAt`,2026-10-11 定稿)、文档。视图应该消费自动数据,让手工字段退为详情页属性——这是重构的设计原则,不只是换布局。

## 方案取舍

### 方案 A(推荐):三撤一合「聚焦」,索引入概览

- 撤 `list / timeline / followups` 三页签,新「聚焦」页签三段:
  1. **要处理**:`followUpBuckets` 前三桶(逾期/今天/本周),行内操作照搬(完成/推进/删除),补关联会话跳转;更晚/未排期折叠一行。
  2. **项目脉搏**:只列有任务/有活动/有 DDL 的项目,紧凑行 = 最近活动 + 风险标 + 未完任务数;空壳项目折叠为一行「N 个未跟踪项目」展开成带过滤框的字母序索引(吸收 S2)。
  3. **接下来 14 天**:到期水平带(时间线的唯一残余价值,替代性收编)。
- 概览底部加项目索引(或聚焦页第 2 段承担,二选一随实现定)。
- 页签 7 → 5:概览 / 聚焦 / 任务看板 / 文档 / 工作日志。
- 关联发现(随方案一并定夺):概览的模块负载图与负责人负载图同建在死轴上(16/16 空),建议下线两图,概览收敛为结论 + KPI + 风险分布 + 马上处理 + 本周到期。
- 被否决的变体:**全并入概览(4 页签)**——概览定位是「全量健康结论」的图表页,混入行动清单后两类信息互相挤压,且「今天开工」失去单一入口。

### 方案 B(最小改动):逐个改造,7 → 6

- 时间线直接删;待跟进并入任务看板(列头排序或「按到期」分组开关);项目列表改索引页(搜索框 + 最近活跃排序 + 行内状态/进度编辑)。
- 否决理由:待跟进与看板合并后,「项目列表」仍是低频报表皮,行动分散两处的问题只解决一半;改动量与方案 A 相当但收敛不彻底。

### 方案 C(仅删不加)

- 只删时间线,列表/待跟进保留。
- 否决理由:不回应大仙「三类都无效」的判断,列表与待跟进的问题原样保留。

### 数据治理侧记(任一方案通用,建议随开发一并做)

- 「一键关联工作区」目前是目录直变项目(`.ssh/home/Downloads` 皆成项目),空壳污染一切视图。建议改为候选确认制(勾选生成)或按会话活跃度排序 + 空壳折叠;最小动作 = 导入后引导补任务/日期,或允许「归档」空壳使其默认不参与任何视图。
