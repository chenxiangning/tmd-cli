# 审批线隔离与精准手术:纯事件归因 · 批审计冻结 · 共改文件 diff 擦除

日期:2026-09-05
状态:已落地(三段分别落在 7b52b27 / 3528300 / 1a89c53;架构结论已沉淀 `architecture/02-code-architecture.md` §checkpoints)

## 背景与目标

产品定约(用户明确):每个会话的审批线独立;会话内轮次独立、不泄露;变更落盘有账本;支持审批/回退/恢复。**隔离优先于覆盖面** —— 宁可漏记,不可串批。

用户实测(springboot-demo,两个并行 omp 会话先后改同一批文件)暴露三层缺陷:

1. **并行串批(P0 前作)**:纯提问的查询会话,四个批的全部文件事件计数为 0 —— 解剖真实账本(`~/.tmd-cli/checkpoints/{md5(cwd)}/ledger.jsonl`)证实内容全部来自并行重构会话与外部进程的写入;同一文件被 3~4 个会话的批重复认领;昨天的死锚点今天还在吞写。
2. **回退后节点内容消失、无法恢复**:回退一个 9 文件批后,过一会儿批缩成 1 文件,「应用回此批」失去依据。实证链:回退/应用给批打 guard → 会话内任何再封口(下一条 prompt 的隐式封口 / sessionExited 兜底)对同锚点做**修订重封** → 按 live 重算文件集时,被回退删除的 A 文件「前后像皆空」被剔出批 → 账本折叠取最后一行,批内容被砍。
3. **共改文件无法拆分回退**:两个并行会话先后写 `SecurityConfig.java`,「内容已变」保护闸整文件拦下 —— 连坐,无法只撤本批的改动。

目标:归因按会话硬隔离;已裁决的批成为不可变历史;共改文件回退/应用按 diff 精准手术。

## 方案取舍

### 一、归因隔离(串批根治)

**选定:events 会话改纯事件归因。** 声明了写入事件检测的 CLI(omp/pi/codex/grok 走磁盘事件流,claude 走 PTY 标记)批内容 = 且仅 = 本会话本轮 edit 行,彻底斩断「全账本无 edit 行路径交给 git 窗口推断补充」的旧通道。代价:shell 落盘盲区(AI 用 bash 写仓库文件不入审批线、不可回退)。

**否决:保留窗口补充 + 修补仲裁。** mtime 只能证明「何时被写」不能证明「谁写的」;外部进程(仓库里并行跑的 zcode/编辑器)根本没有锚点窗口可用来否决,「最近锚点者赢」在重叠期是抛硬币 —— 修补封不住口,实证已两次用户报障。

**否决:PTY 输出解析推断写入者。** 需解析 bash 命令与输出意图,脆弱且误判即静默覆盖,违背宁漏勿串。

**否决:按 CLI 分会话目录隔离账本。** 账本键已按 (cwd, sessionId, turn) 三元组隔离,泄露不在存储层;拆目录反而破坏「同工作区一套账」的回退语义。

### 二、git 归因仲裁(无事件信号 CLI 的兜底)

**选定:三道闸,宁漏勿串。** ① 认领优先:外会话锚点窗口内已认领的路径(封口批 turn_files ∪ events 链 edit 行)我方不再归属,根治重复认领与无信号 CLI 抢事件链文件;② 落窗最近提示者赢(顺序场景的既有正确行为,回归测试锁死);③ 僵尸封顶:开放锚点窗口超 `STALE_OPEN_MS`(30 分钟,与幽灵收口同值)视为关闭,昨天的死锚点不再吞今天的写入。

**否决:任何外会话窗口重叠即弃权。** 顺序场景(他人空闲在轮与轮之间)会被误伤,B 自己的写入进不了自己的批 —— 既有并行归属测试直接翻红。

**否决:不处理 git 会话,只做 events。** kimi/qoder 等无信号源 CLI 的审批线会继续互相吞批;三道闸成本低且把重复认领一类确定性错误清零。

### 三、批审计冻结(节点内容消失根治)

**选定:guard 存在即冻结。** 批一旦发生回退/应用(审核态带 guard_id),`build_turn_entry` 直接跳过 —— 固化的变更集即成历史,任何再封口不再重算。反悔清除 guard 即解冻;此时内容已回到批后像,重封与原批等值,`same_revision` 保证不产生冗余修订。应用后落新 guard,继续冻结。

**否决:修订重封时按 reverted_paths 把已退文件补回。** 回退是用户对已封口批的裁决,批自此是历史快照;「重算 + 补回」要维护两套真值,且 next-turn 的 `latest_turn_after` 前像链、live 分类都要跟着分叉,复杂度不可控。

**否决:回退时把批条目重写为不可变标记。** 账本是追加写,条目不可变由「不再追加修订」实现即可,加标记字段是同义反复。

### 四、共改文件 diff 精准手术

**选定:自研行级补丁引擎(`patch.rs`,约 200 行)。** 每批的批前像/批后像本就固化在 sidecar —— 「本批对某文件的改动」= 一条确定 diff。回退 = 把「批后像→批前像」补丁以精确上下文匹配(3 行上下文,hunk 在期望位置 ±250 行窗口内找整行字节等值的唯一匹配)应用到 live;应用 = 「批前像→批后像」精准重放。命中即只动本批 hunk,他人写入保留;失配 = 改动重叠,跳过并显式列出,绝不静默覆盖。范围限定 M 文件(双像俱在);A/D 文件与前像缺失者无对齐基线,维持保守跳过;LCS 带格数上限(1M),超大文件放弃手术走保守路径。

**否决:git2 的 `merge_file_from_index`。** git2 0.20 未暴露无仓库的 `git_merge_file`;index 路径要求三份内容写进**用户仓库**的 odb,违反 checkpoints「永不触碰用户仓库」铁律。

**否决:shell-out `git merge-file`。** checkpoints 引入 git CLI 依赖(此前只有 git 插件远端操作走 shell-out),冲突/失败语义难以内存化,错误处理经字符串协议太脆。

**否决:引入 `similar` 等 diff crate。** 新依赖须过 spec 论证;需求边界清晰(单文件、行级、上下文匹配、≤8MB),自研可控且测试锁定。

手术成功的文件同样写 guard(反悔 = 写回手术前一刻的完整内容),与既有安全链无缝;不改变「回退后批冻结」。

## 改动面

后端:`checkpoints/{events,attribution,ledger,view,restore,apply}.rs` 归因分支与仲裁、`patch.rs`(新增);前端仅 `BatchRow.tsx` 回退/应用确认框文案。契约不变:IPC 签名、账本格式、states 语义均无破坏性变更。

## 验证

- **账本实证法**:直接解析生产 `ledger.jsonl`(折叠规则同 `load_ledger`),按 (session, kind, turn, editCount) 复原每批归属 —— 泄露批全部 `editCount=0` 即窗口推断所为,修复后同查询应无 `ec=0` 的他人文件。
- **测试**(cargo 170 全绿,+10):泄露回归「events_会话不吞外部与并行写入」、「并行会话_git归因不抢事件链认领的文件」、「外会话封口后再写_认领窗口不拦新写入」、「回退后批次冻结_修订重封不丢已退内容」、patch 单元 3(擦除重放互逆/同区域重叠返回 None/无差异原样)、共改集成 3(精准擦除保留他人写入/同区域重叠拒绝覆盖/回退后带他人写入精准重放应用);两个旧契约测试按新定约改写(shell 落盘不入批、手术失败原因「改动重叠」)。
- **静态**:clippy -D warnings / fmt;前端 typecheck + vitest 790、arch-boundary、file-size 全绿。
- **真机目检(待办)**:两并行 omp 会话(一纯提问一改文件)→ 提问会话审批线保持空;共改同文件后回退先封批 → 另一会话的改动仍在文件里;回退 → 继续对话 → 批内容不缩水、应用回此批完整恢复。
