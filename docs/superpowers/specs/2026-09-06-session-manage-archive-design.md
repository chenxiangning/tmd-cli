# 会话管理模式 + 归档视图 设计 spec

- **日期**:2026-09-06
- **状态**:已落地(实现随本 spec 提交)
- **作者**:大仙 + omp(glm-5.3-flash)

## 背景与目标

左侧工作区的会话列表只有逐条右键操作,批量整理(删历史、归旧会话)效率低。本设计给 CLI 分组加一个「会话管理」面:

1. 分组段头(展开态)hover 显形一个图标开关,点击进入/退出该组的管理模式;
2. 管理模式下每条会话带复选框,行尾带归档/删除按钮;支持左键按下拖动的范围多选(mail 式),配批量条(归档/恢复 + 两步确认删除);
3. 归档 = 切换会话状态(应用侧覆盖层,不写 CLI 磁盘):默认视图隐藏归档会话;「工作区」标题右侧新增「默认|归档」视图切换,归档视图反向只看归档项,行首圆点换成「归」字。

非目标:归档不写回各家 CLI 私有存储;不做跨工作区归档视图;不做移动端/触摸支持。

## 方案取舍

### 归档状态存哪:应用侧覆盖层(kernel) vs CLI 磁盘

- **选定:kernel/sessionArchive.ts + settings.sessionArchive**(与 sessionPins/sessionTitles 同构,key = `workspaceId:profileId:cliSessionId`)。理由:各家 CLI 会话文件是定长 pad / 私有格式,写回有解析破坏风险(架构决策沿用命名覆盖层先例);归档是 tmd-cli 自有语义,零 Rust 改动。
- 否决:写 CLI 磁盘(改写他人格式风险 + 9 家 CLI 各写一套);存 localStorage(污染 settings schema 之外,违反「一类产出一个去处」的 settings 单例)。

### 多选交互:拖选扩散 vs 逐个点选 vs marquee 框选

- **选定:按下锚定 + 滑动扩散**(锚点行 toggle 后,指针扫过的行 [anchor..cur] 向锚点新状态对齐;命中测试用 `elementFromPoint`)。点按 = 单行 toggle 是同一代码路径的自然退化;无需考虑拖框的滚动态。
- 否决:纯逐个点选(用户明确要长按滑动);marquee 矩形框选(竖列表里无增量价值,还要处理滚动与反向框)。
- 落地修正:批量条渲染在行集**之后**(列表尾部)——首版放列表顶部,选中即插条会把行往下顶,拖选途中坐标漂移(实测只选中 1 行);挪到尾部后插条不移动已有行,坐标稳定。

### 管理开关放哪:段头内 span vs 段外悬浮钮

- **选定:GroupHeader 内 span**(段头本身是 button,禁嵌套 button,先例 PinToggle),hover 显形、激活常亮;仅 CLI 组展开态注入,终端/SSH 组无磁盘会话语义不渲染。
- 否决:悬浮在分组上的独立按钮(多一层定位与遮挡处理,还挡行内容)。

### 删除确认:两步武装 vs 直接删

- **选定:两步武装**(首击进确认态 3s 自动解除,再击执行),行内按钮与批量条同一 `DangerAction`;与右键菜单删除的两步确认同语义。物理删除路径复用 `sessionOps.ts`(自 SessionList/LiveSessionRow 拆出,文件规模铁则),删除时同步清命名/置顶/**归档**覆盖层,防止 flag 残留成死数据。

### 归档视图的行来源

- 归档视图直接取磁盘扫描集 `sessions` 过滤归档 key(**含绑定活会话的条目**:默认视图其活行隐藏,归档视图以磁盘行形呈现,点击经 openDiskSession 回到会话);置顶块/活行区不渲染,分页复用原 limit 机制。

## 验证

- 单测:`kernel/sessionArchive.test.ts`(key 构造/归档幂等/取消 no-op/与置顶隔离/sanitize 白名单 + workspaceArchiveView 回落);`plugins/workspace/sessionManage.test.ts`(selectRange 加选/取消/向上扩散/越界跳过);settings 默认值测试补新键。
- 门禁:`pnpm typecheck && pnpm test`(935 全绿)&& `pnpm check:arch-boundary && pnpm check:file-size && pnpm build` 全过。
- 真机交互目检(vite dev 1421 + Tauri IPC 桩注入,等效真实数据链路):
  - 段头图标默认隐藏 → hover 显形(opacity 0→1)→ 点击进管理模式(复选框行 + 行尾归档/删除钮);
  - 左键按下拖过两行 → 「已选 2」批量条出现,两行选中态;
  - 批量归档 → 默认视图隐藏、批量条消失;切「归档」视图 → 两条带「归」字徽记的磁盘行;
  - 管理模式内单行「恢复」→ 会话回归默认视图;行删除两步武装 → `fs_remove_path` 收到精确路径(桩 fs 记录);
  - 归档视图空组不占位;视图切换重建管理行集(key 复位,选中态不跨视图携带)。

## 落地修订(2026-09-07)

- **归档容量语义**:方案取舍未覆盖满额行为;实现最初为「满 200 条拒绝新 key」,
  用户归档数到顶后每次归档静默无效(实测踩坑:「归档时灵时不灵」)。改为满额
  **逐出 `archivedAt` 最旧条目** —— 归档条目只是可见性时间戳,逐出零数据损失,
  与 sanitize 逐出对称。回归用例钉在 `kernel/sessionArchive.test.ts`。
- **活会话删除顺序**:本 spec 沿用「先删盘再 kill」,有两个实测时序洞(症状
  「有时候删不下去」):① 删完到 kill 生效的缝隙里,流式中的 CLI 按路径重开文件,
  会话死而复生;② 扫描快照未命中(懒落盘 CLI 首写晚于 spawn 35s+)时压根不执行
  删盘,文件幸存被重扫列回。契约改为**先 kill 并 await,再删盘;快照未命中现扫
  反查兜底**,沉淀进 `architecture/02-code-architecture.md` §5.1 共性法则 3;
  契约测试 `plugins/workspace/sessionOps.test.ts`。
- **归档视图分页独立水位**:正文「分页复用原 limit 机制」有缺陷 —— limit 是
  默认/归档两视图共享的单值,默认视图「更多」翻过的页数直接放大归档列表
  (用户实测:切归档视图一次性摊出上百条,形同全量显示)。改为**两视图各自持
  独立水位**,各从配额起步、「更多」各自翻倍;预算修改仍双视图同时重置。
