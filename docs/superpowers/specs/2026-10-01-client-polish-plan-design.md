# 客户端界面与功能交互打磨设计方案(分级治理,双端)

日期:2026-10-01
状态:已实施(待用户检查;真机目检清单见文末实施注记;未提交;用户已拍板取向=分级治理、范围=桌面+手机;调研依据 `docs/research/client-polish-half-month-audit.md`,P0×3 / P1×30 / P2×45 / 重度 demo×2 / 中度×12 / 轻度×14)

## 背景与目标

近半个月 9 版(v0.1.9..v0.2.7)高速交付 40+ 新功能面,骨架质量高,但打磨欠账集中在:手机端 UI 消费层(通知链路近乎不可达、错误伪装空态、3/10 transcript 契约)、「能力门宽于实际能力」的跨引擎长尾(入口能点进去才失败)、以及五个系统性模式(失败伪装空 / 能力门过宽 / i18n 半途 / 形制漂移 / 覆盖长尾)。前轮 `ui-polish-0.2.5-to-0.2.7.md` 已修 65 项视觉与交互边角,本轮处理其余全量。

目标:

1. **诚实性**:失败不伪装成空态/永久加载;声明与实现一致(文档、引导文案、入口能力);无死钮死入口。
2. **高频路径闭环**:通知、检索、接力、审批、结构化会话这些日用路径做到「每个动作有反馈、每个失败有出路」。
3. **demo 功能分级处置**:逐个裁决补全 / 收敛 / 下线隐藏 / 留观,不搞一刀切全面补齐。
4. **立机制防复发**:五个系统性模式各有一个统一解,写入惯例,不再逐点打补丁。

非目标:不新增大功能面;不动架构分层与插件边界;引擎覆盖只按价值分级推进,不做全面补齐;不做手机平板双栏等大布局工程。

## 方案取舍

| 方案 | 取舍 | 理由 |
|---|---|---|
| **分级治理(选定)** | demo 功能逐个裁决:高价值补全到产品级、低价值收敛(如实标注)或下线隐藏;打磨精力优先高频核心路径 | 3 P0 全部是信任级缺陷(死钮/通知失效/红标缺面)必须修;引擎长尾(6 家 TUI 回落、7 家 transcript 契约)部分受 CLI 自身能力限制,全面补齐性价比低;收敛+入口分档既守住「缺失不猜」纪律又不误导用户 |
| 全面补全(否决) | 所有 demo 功能补到产品级 | 工作量数倍拉长打磨周期,违背「打磨」本意;dsh 无 skill 体系、pi 无 MCP 写回等缺口在 CLI 侧无解;部分覆盖缺口(远端分支列表、手机全文检索)依赖桥命令域扩展,超出界面交互打磨边界 |
| 只磨界面交互(否决) | 功能覆盖度不动,只做视觉/反馈/键盘一致性 | P0 三项中两项是功能交互层缺陷(通知链路、红标缺面),手机错误伪装是信任问题非视觉问题;「AI 说画了但画布空」「模型提问被静默替答」这类问题磨皮解决不了 |

## 实施波次

三波串行,每波独立可验收、可提交;波内条目可并行分域实施。

- **第一波·诚实性(P0 + 信任级)**:P0-1/2/3 中 P0-1、P0-3 立即修(P0-2 归第二波通知主题整体修);失败伪装空全族(手机 M1-M3、看板 E7、open-with E3);死入口清零(structured rail 钮 F1、HubEntry 停用态);声明与实现不符(web-access E1/E2、LSP E5、marks E6、高危红标);手机形制修复(M6 .sheet、M7 死类)。验收:全仓无「点击无反应」「错误渲染为空/永久加载」「引导指向不存在控件」三类;grep `catch(() => \[\])` 在 UI 消费面清零(数据装配层豁免需注释)。
- **第二波·高频路径闭环**:通知闭环(手机 P0-2 检测面+willPresent、桌面 B1 点击深链、B4 多幕布额度);检索 B6;接力 B2;结构化会话 F2 部件占位+exited 重开+输入面最小集;意图画布 C1;学堂 B3/B5;GenSettings F3 形态标注;relay/接力配套;手机 M4 水位回放、M9 截断提示、M10 exit 消费、M11 远端分支说明、M5 i18n t() 化;web-access QR;卫生清扫回执;mcp-hub C3 文案;skill-hub C4 已装视图。验收:每个高频动作有反馈、失败有重试或说明;两份真机清单(见验证)通过。
- **第三波·机制沉淀 + 覆盖长尾**:统一机制四件收口(下节);引擎覆盖定向补(手机 transcript codex/qoder、sessionUsage kimi/grok);手机 i18n 语言跟随落地(或裁决止损);引擎表单源化;wallpaper lite 删除;spec/proposal 漂移 3 处修订。验收:机制各有惯例文档或 CI/check 落点;覆盖矩阵更新两格以上。

## 统一机制(怎么修,贯穿三波)

1. **错误信封**:异步取数统一「loading / data / error(可重试) / empty」四态信封,失败绝不折叠为默认值——把 0.2.2 给 fs_search 立的「不伪装空结果」规矩推广为全仓 UI 消费面纪律;优先在手机端做基座(重灾区),桌面逐面跟进。
2. **能力门分档**:入口显隐/标注跟随真实能力而非「有适配器」——capability 判定收敛为插件声明(profile 声明面已有先例),同一能力多入口(rail 钮/pill/选择器)共用一档;「引擎支持矩阵」以 cli-shared 单一数据源供给(消三处手抄)。
3. **i18n 收口**:跑一次 t() 键 × 三语词典全量 diff(脚本化,可入 CI)清零缺键与死键;立惯例——常量表严禁模块顶层求值 t()(组件内求值),新增 UI 文案 review 必查词典;手机语言跟随系统。
4. **弹层/sheet a11y 基建**:桌面 DialogShell 类弹层补 role="dialog"/aria-modal/焦点圈闭/Esc,五个新弹层接入;手机 sheet 统一基座组件(Esc 不可用但焦点管理与关闭出口统一);一次建设全仓复用。
