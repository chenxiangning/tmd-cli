# 活轮过程内容批次折叠:滚动窗口只留最新 3 个思考/工具条目

日期:2026-11-06
状态:已确认(用户拍板:窗口恒定 3 个且必须含思考;折叠头复用落定态整体折叠头;只作用于进行中的轮)

## 背景与目标

RPC 对话(结构化会话)的活轮渲染(`liveTurn.tsx`)目前把已输出的思考段、工具段全部全文铺开,只有**轮结束落定时**才由 `SsTurnView` 的 `SsProcessFold` 把整轮过程折成一行「思考 N 次 · 工具调用 M 次 ›」。代理多步轮动辄十几次思考 + 几十次工具调用,轮未完页面已超长。

目标:

1. 轮进行中,已输出完的思考/工具内容**滚动批次折叠**:始终只全文展示**最新 3 个**过程块(reasoning + tool 混池计数),更早的依次收进一个折叠组头;
2. 折叠头**复用落定态整体折叠头的形态与文案**(`SsProcessFold` 头),点开可回看完整过程,点开后保持展开(手动接管,新块仍继续折进头里);
3. **落定时整体折叠逻辑保持不变**:轮一结束,整轮过程照常折成一个大组头并播「展开→收起」结算过渡,批次折叠状态零残留;
4. assistant 正文、system 块不参与计数,照旧常显。

## 方案取舍

**选定:渲染层纯函数切分。** 新纯函数 `splitLiveWindow`(本插件 `ssLiveWindow.ts`):输入轮内过程块序列,输出 `{ head, visible }`——`visible` = 可见窗(最新 3 个,含思考约束),`head` = 收进折叠头的更早块。`LiveTurn` 按切分结果渲染:head 块在首个 head 块位置渲染一个复用的 `SsProcessFold`(默认收起),visible 块照旧分段渲染。

理由:折叠归属完全由块在池中的序号推导,确定性、可单测,无"哪批折过"状态,轮结束切换 `SsTurnView` 路径时天然归零,无跨轮泄漏。

**否决:状态机渐进折叠**(每批各成一个折叠头)。用户明确"收成一个折叠头";多批次头只会复刻落定态展开区的形态,增加状态面与动画编排,无收益。

**窗口计数规则(用户 2026-11-06 补拍板:窗内必须含一个思考输出)**:

- 过程块 ≤ 3 个:不折叠,全部可见;
- > 3 个:默认可见窗 = 最新 3 个;若窗内**没有 reasoning 块**,挤出窗内最老的一个工具块,换入其之前最近的思考块(窗仍 3 个,保证最近思考常显);
- 轮内尚无任何思考块(开头直接连发工具):约束不触发,可见窗 = 最新 3 个工具。

## 渲染与样式

- 折叠头直接复用 `SsProcessFold`(从 `ssTurnView.tsx` 导出),不传 `enterOpen`:默认收起、头文案「思考 N 次 · 工具调用 M 次 ›」、grid-rows 开合动画、手动接管逻辑全部同落定态;展开区 = 折叠块按原序 groupSections(思考段 + 树形工具导轨行)。
- head 块在块流中的首个 head 块位置渲染(assistant/system 块穿插照常常显于原位);head 块全部前置于 visible 块(head = 最老的过程块,序号恒小于窗内块),故折叠头位置唯一且稳定。
- 流内活跃思考块(「思考中…」pulse)天然位于最新块,不受切分影响。
- 无新增 CSS、无新增 i18n 键(复用 kernel「思考 {n} 次」「工具调用 {n} 次」)。
- 落定路径(`SsTurnView` / `ssSettleKey` / `ssTurnLive`)零改动;PTY 与 mobile 树零接触。
