# 0.4.8 可恢复、可审、可交付工作流设计

日期:2026-11-01
状态:已落地(2026-11-02;大仙指令「排期开始开发吧」)

## 背景与目标

0.4.7 后,客户端已有 10 个 CLI 与 48 个注册插件。当前缺口不是功能数量,而是主工作流的五个断点:

1. 插件市场重启可绕过未保存内容确认。
2. WSL 远程编辑无乐观锁,远程 Git 路径直接插入 shell。
3. structured-session 没接入 checkpoints、footprint 与接力,结构化程度越高,工作证据反而越少。
4. CLI 进程仍存活但回合失败时,没有同引擎的上一回合重试入口。
5. worktree 创建后,diff、PR 与安全清理分散,缺少明确收尾路径。

目标:不新增任务系统、不替换 PTY 主链,复用现有契约串起「发送 → 存证 → 审阅 → 失败恢复 → 交付」。

## 方案取舍

| 主题 | 选定 | 否决 |
| --- | --- | --- |
| 重启安全 | 抽取并复用关窗的聚合确认、草稿 flush 与强制关闭协调链 | 在市场页另写一套确认框;绕过既有 tab 闸 |
| WSL 版本令牌 | 文件来源读写契约携带可选 mtime＋长度;WSL 读写伴行 stat,冲突复用现有编辑器横幅 | 新锁服务;所有远程来源强制迁移;只读文件不改行为 |
| 结构化存证 | structured-session 直接复用 checkpoint 锚点、成功写工具入账和封口;footprint 消费同一结算事件 | 把 RPC 会话伪装成 PTY host session;另建一套变更账本 |
| 上一回合重试 | 预览最后一条用户消息并回填 composer,用户显式发送 | 自动重发;自动错误分类;忽略前轮已产生的文件副作用 |
| worktree 交付 | 按脏净状态串联现有 diff、分支比较、CreatePR 与安全移除 | auto-merge;自动删树;新 Git 工作流引擎 |
| 协议扩张 | 本批只统一现有工作流 | ACP、opencode server、Variants 同步开工 |

## 设计

### 1. 插件市场重启保护

- 仅有待生效插件变更时强调重启动作。
- 点击重启后,先刷写草稿镜像,再走与关窗相同的未保存内容聚合裁决。
- 用户取消:市场页、编辑 tab、活动会话与草稿全部保持原状。
- 用户确认:走 `requestCloseAllTabs({ quit: true })` 的退出协调,再调用现有重启命令。
- 重启后沿用现有会话现场恢复;不新增恢复格式。

### 2. WSL 写入安全

- 文件来源读取结果可携带版本令牌 `{ mtimeMs, len }`;本地现有乐观锁口径不变,其他远程来源可缺省。
- WSL 读取在同一次远程脚本中返回内容与 stat,避免读内容后再读版本产生额外漂移窗。
- 保存携带打开或上次保存时的期望版本。远端版本不符即拒绝写回,复用 `E_FS_MTIME` 与「覆盖 / 重读」横幅。
- 用户选择覆盖:显式绕过期望值;选择重读:重新拉取内容与版本令牌。
- `useRemoteGitStatus` 不再把 `linuxRoot` 直接插入 shell。复用 b64 脚本通道和安全参数引用;空格、引号、美元符号、反引号与 `$()` 路径不得改变命令语义。
- 保留 6KB 分块、原子写、512KB 上限与 60s 写超时。

### 3. structured-session 共同存证与接力

- prompt 发送时记录 checkpoint 锚点,携带引擎、模型、思考强度与 cwd。
- reducer 只把成功的 write/edit 工具完成帧转成文件写入事件;其他工具不猜测文件副作用。
- 回合结束按既有 checkpoint 封口路径结算,并发出 footprint 已消费的 `ckptTurnSealed` 事件;失败进程不伪造完成轮。
- 批次、时间线和足迹可深链回 structured-session tab;没有 PTY 的位置不显示「定位幕布」。
- 头部增加「接力」入口,复用 relay 对话框。摘要来源使用当前结构化 blocks,并保留 cwd、workspaceId 与标题。
- 断线 resume 后沿用同一 CLI 会话身份与 cwd,不另开账本命名空间。

### 4. 上一回合预览重试

- 会话菜单与结构化会话头部提供「重试上一回合…」。
- 数据源依次为当前会话最后一条真实用户消息、磁盘转录最后一条用户消息;控制命令、接力自动注入外壳不作为新任务正文。
- 弹层显示原文与目标会话,并提供「对应 checkpoint 批次」入口(存在时)。
- 确认后只回填 composer,不自动发送。进程已退出时先走现有 `openDiskSession`,再用 pending prompt 队列注入。
- 跨引擎继续走既有 relay,不在本功能里复制接力逻辑。

### 5. worktree 审阅与交付

- WorktreeZone 的非主仓树增加「审阅 / 交付」动作。
- 脏树:打开该 worktree 的现有 diff 视图,不默认切分支、不隐藏未提交改动。
- 干净且已提交:打开现有 BranchCompareModal;基线使用当前仓库已配置的上游或既有比较默认值,不硬编码 main。
- 需要 PR:从比较结果进入 CreatePrDialog,预填当前 worktree 分支为 head。
- PR、合并后仍由用户显式调用现有安全移除;未合并分支与脏树保护不变。

## 验证

- 重启:有脏 tab 取消后零变化;确认后草稿 flush、重启与现场恢复成功;无待生效变更时不强调重启。
- WSL:外部改盘后保存必拒;覆盖与重读两路径正确;特殊字符路径不产生注入副作用;大文件与冷启动不回归。
- structured-session:prompt → 成功 write/edit → settled 全链产生批次与足迹;失败工具不入账;resume 不串账;接力可预览。
- 重试:活会话与已退出会话均只回填不直发;空历史无死按钮;重复点击不叠 pending;对应批次可打开。
- worktree:脏树、干净树、无上游、未合并分支四态分别可达且不误删。
- 每个非平凡分支补最小契约测试;跨插件数据流做 1421 桩端到端冒烟。
- 收口执行 `pnpm check:gate`、Rust `cargo test && cargo clippy --all-targets -- -D warnings && cargo fmt --check`、`npx react-doctor@latest -y` 100。
- UI 改动经 `pnpm tauri:dev` 真实窗口目检;移动 M2 与桌面洪水矩阵另按现有验收单执行,不能用单测替代真机结论。
