# 规则体检运行态交互精修设计

日期:2026-10-28
状态:方向已确认(大仙选择「运行态精修」),书面 spec 待评审

## 背景与目标

规则体检已具备中央行级 loading、阶段进度与右栏实时日志,但运行闭环仍有四处断点:日志每次更新强制滚底,用户无法稳定回看;失败后右栏仍显示完成态;运行中引擎与模型可切换,展示选择可能与本次运行不一致;幕布写死深色,浅色主题与状态对比不一致。

目标是在不改变现有中央报告 + 右栏日志布局、不修改 lint 流水线与 PTY 契约的前提下,补齐可理解的进度、可控制的日志、可信的操作状态与完成/失败反馈;右侧入口统一更名为「AI配置管理」。

## 方案取舍

**选定:运行态精修。** 复用 `lintController` 已有的 `running/progress/error/log/waitSec/liveBytes` 与内核 `Spinner`,只调整 `memory-coordinator/lint` 的展示和交互,并同步面板注册文案。

- 中央运行页保留规则分组与当前规则卡;脚本阶段显示阶段进度,AI 判定显示真实 `done/total`,未返回时显示等待时间与输出状态,不按等待时长伪造百分比。
- 右栏日志仅在视图位于底部时自动跟随;用户上翻后保持阅读位置,显示「回到最新」按钮,点击后滚到底并恢复跟随。原始 PTY 尾窗保持原样透传,不增加 Markdown 或气泡。
- 运行中禁用引擎/模型选择,启动按钮呈现进行中文案;完成、失败分别使用成功、错误语义,不再仅凭 `running=false` 推断成功。
- 颜色改用现有 `--tmd-*` 语义变量;复用 Phosphor 图标与 `Spinner`,不新增依赖。加载区域提供 `aria-busy`/进度语义,动态摘要不要逐条打断屏幕阅读器,动画遵守减动效设置。
- 入口注册、面板导航 aria 与 en/ja 词典统一使用「AI配置管理」对应译文;中文以用户指定文案为唯一口径。

**否决:整体布局重构。** 中央报告与右栏职责已经明确,重排只能增加视觉差异,不能解决上述状态缺陷,且回归面扩大到报告审核与应用链路。

**否决:仅样式替换。** 改颜色或 spinner 无法修复强制滚底、失败误报完成和运行中配置漂移,交互问题会原样保留。

## 状态与错误处理

视图状态只从现有控制器推导:`running=true` 为运行中;否则 `error` 非空为失败;已有最终结果且无错误为完成。模型引擎错误继续保留部分脚本结果,不新增重试、取消或后台任务机制。日志跟随只是视图局部状态,不进入共享控制器,也不影响日志上限和心跳去重。
