# 活动守望证据分级模型(轮次状态机重构)

日期:2026-09-11
状态:已落地(fa8a020)+ 已评审(独立评审 5 findings:守卫塌缩为「未应答写入天花板」修 F1/F5,闸 4 前置修 F4,F2/F3/F6/F7 钉 08 契约 §3/§6)—— 活契约以 docs/architecture/08 为准

## 背景与目标

侧栏三态标签(运行时 / 空闲-未查看 / 空闲)由 `activityWatch.ts` 从 PTY 字节流时序反推:用户写入开轮 → 输出推活动钟 → 静默 >2s 结算。CLI 不提供机器可读的轮次边界,这一约束不可绕过,问题在于现行实现是**二值证据**(输出 = 活动 / 闸掉 = 无视),六层特判闸(首写闸、轮次开启闸、重绘抑制窗、空闲重绘闸、思考期守卫、spinner 活性界)逐个堵反例、彼此咬合,一个闸改变「什么算静默」就动摇别的闸的推理前提(2026-09-11 一天之内「空闲重绘闸 → P0 假结算 → 思考期守卫」互为因果)。

真实字节流实证(2026-09-11,omp 18.1.17,53s 完整轮次,1248 帧带毫秒时戳,`/tmp/omp-lifecycle-probe/capture.jsonl`):

- 回合期页脚每秒跳 elapsed 计数(「9s→10s」):**字母骨架恒定、数字每秒变动**;
- 空闲期页脚原地自绘:**骨架恒定复现、数字不动**(36 帧仅 4 种骨架);
- 整轮回放经现行 ActivityWatch 无一次提前结算 —— omp 18.1.17 在现行实现下行为正确,「会话结束」误读已由标签更名(commit bd1a8a0)解决一半。

目标:把六层特判收敛为「一个分类器 + 一条结算公式 + 一个开轮锚点」,修掉两个已知盲区,对外 API 与既有行为零变化。

## 方案取舍

**选定:证据分级模型(单文件重写 activityWatch.ts,对外接口不变)。** 每个可见分片按「字母骨架 + 数字串」三级分类:

| 级别 | 判据 | 语义 | 时钟效果 |
|---|---|---|---|
| content | 字母骨架首见(新词新字母) | 真实流式产出 | 推 `lastContentAt`,可开轮 |
| tick-chrome | 字母骨架复现 + 数字串变动 | 活着的家具(elapsed/时钟/token 计数) | 推 `lastTickAt`(证据钟),不开轮 |
| static-chrome | 字母骨架复现 + 数字串相同(或骨架为空) | 死的家具(spinner 原地转、状态栏重绘) | 只记 `lastStaticAt`(守卫活性) |

结算公式(1s tick):`静默 = now − max(lastContentAt, lastTickAt) > 2s`,且不被守卫扣住。守卫只保护「未应答的用户写入」:

```
awaitingTurn && !answered && (
  (evidence && now − lastStaticAt < 2s)      // spinner 还在转(思考期守卫语义,原样保留)
  || (!evidence && now − lastWriteAt < 120s) // 空轮宽限:写后全静默,120s 内不结算(新盲区修复)
)
```

- 骨架正则从「字母+数字」收紧为**仅字母**:数字跳动类家具(空闲页脚墙钟、版本号、计数器)整体归入 chrome,不再伪装内容;omp 回合保持改由 tick-chrome 证据承担(实证等价)。
- 空轮宽限修掉现行盲区:现行守卫要求「2s 内见过 chrome」,完全静默的 CLI(无 spinner 无 footer)写后被 2s 假结算吞 `awaitingTurn` → 真实应答被轮次开启闸拦死。120s 后照常结算兜底(写入丢失/CLI 挂死不得永挂运行时)。
- 思考期守卫与 spinner 活性界不再是特判,是公式里的一项;`answeredSinceWrite`/`lastGatedFrameAt` 两张独立 Map 并入每会话单一状态对象(12 张 Map → 1 张)。

**否决:逐 CLI 适配(方案 1)。** 各家 TUI 模式没有机器可读轮次信号,RPC 模式要弃用幕布(换掉产品形态);适配面 = 每家插件 + 上游每次升级重对齐,且违反「内核不懂 CLI 私有格式」。

**否决:结算后复活(强证据重开轮)。** 终端直打已证实走 `host.writeSession` 唯一写入口(TerminalView.onData → writeSession → onUserWrite),真实输入不需要复活;复活会重开 2026-09-08 hook/dreamer/banner 异步噪音误标未读的洞。

**否决:chrome 全程持轮。** 初稿设想「静态 spinner 持住任何阶段的轮次」——被实证否决:回合期静态 spinner 与空闲页脚同为「恒定字母骨架」,字节上不可分;若全程持轮,答完后的空闲页脚(永续自绘)会让轮次永不结算。omp 回合保持的真实机制是**数字变动**(tick-chrome),静态自绘只能按现行语义仅在未应答窗内有效。

## 诚实边界(字节流信息论极限)

1. 应答开始后**完全静默**的工具执行期(无 footer 无 spinner 无输出)>2s 仍会假结算 —— 与真结束不可分;有 elapsed 计数的 CLI(omp 实测)由 tick-chrome 免疫。静态 spinner 的 CLI 中轮静默维持现行语义(提前翻、用户新写入自愈),钉为既定行为。
2. 永续跳动的空闲墙钟(秒级)与运行中计数不可分,此类 CLI 轮内持轮无上限(与现状持平)。
3. 纯数字应答(罕见)判 chrome,未读归属退化到旧字节时间。
