# 工作台空壳项目批量归档设计

- 日期:2026-10-17
- 状态:已立项待评审(0.3.9 批次二;只出 spec,码量不在 0.3.9)
- 上游:`docs/review/2026-10-15-038-debt-cleanup-review.md` 挂账清单(手工清 13 空壳后立的长效治理项)、`docs/brainstorm/2026-10-17-039-next-steps.md`

## 背景与目标

0.3.7 一键关联无预选批量导入产生 10 个空壳项目(零任务零文档零更新),污染概览 KPI / 风险环 / 进度分布 / focusLine(实测:平均进度 6%、风险环「未排期 14」)。0.3.8 已手工清 13 个(16→3,文件级备份后删),防新增已由 `LinkWorkspacesDialog` 候选勾选 + 点开头目录默认不勾兜住。但「关联一批工作区 → 实际只跟三五个」是 recurring 场景,手工清不可持续。

目标:概览提供「空壳批量归档」入口,一次把空壳项目移出全部统计面,可逆、有取证。

非目标:不动单项目删除链(已有);不做定时自动归档(误伤风险 > 收益);不改空壳判据本身。

## 方案

复用现有空壳判据 `pulsePartition().ghosts`(无未完成任务 ∧ 无 DDL ∧ 近 7 天无活动,`focusModel.ts`),零新判据。

交互面:概览「N 个未跟踪项目」行尾加「清理空壳」入口(仅 ghosts.length ≥ 2 时渲染) → 弹层列空壳清单(默认全勾,可反勾) → 确认批量归档。归档 = 项目 status 置 `archived`(新增枚举值)+ `archivedAt` 时刻,**不删任何实体**;归档项目退出概览/看板/聚焦全部统计与列表,项目列表底加「已归档(N)」折叠段可逐个恢复(status 回 `active`)。

防误伤:判据只认 ghosts(7 天无活动缓冲已兜住「刚关联还没动工」);确认弹层逐行列名,无「全选不可见项」批量路径。

## 方案取舍

| 决策 | 选定 | 否决与理由 |
|---|---|---|
| 处置语义 | 软归档(status=archived,可恢复) | 硬删除(0.3.8 手工路径)——不可逆,批量场景误伤无退路;备份文件散落在用户目录无恢复面 |
| 判据 | 复用 `pulsePartition().ghosts` | 新立「零任务零文档零更新」判据——与聚焦页脉搏判据双份真相,0.3.7 空壳定义漂移就是这么来的 |
| 入口 | 概览未跟踪行尾,≥2 才渲染 | 常驻工具栏按钮——空壳是低频治理面,常驻占位不值 |
| 自动化 | 不做定时/静默归档 | 自动归档「7 天没动的真项目」= 误伤;治理动作必须过人眼 |
| 恢复面 | 项目列表底「已归档」折叠段逐个恢复 | 归档弹层内撤销窗——一次性 toast 撤销过期即丢,折叠段是持久面 |

## 改动面预估

- `store.ts` / 类型:Project.status 加 `archived` + `archivedAt?`;统计消费面(概览 KPI/风险环/进度分布/focusLine/看板)统一过滤 archived(单点:selector 层)。
- 概览行尾入口 + 归档确认弹层(复用 `LinkWorkspacesDialog` 勾选行模式);项目列表「已归档」折叠段。
- i18n:约 6 键三语。
- 预估 4 文件 + 2 新文件,无 kernel/Rust 改动。

## 验证

- 单测:archived 过滤 selector(概览计数与列表一致);归档/恢复往返幂等;ghosts ≥2 门控渲染。
- 桩目检(1421):造 3 空壳 + 2 真项目 → 入口出现 → 反勾 1 个归档 2 个 → 概览计数同步减 → 已归档段恢复 1 个 → 统计回升。
- 真机目检:概览 KPI/风险环归档前后对照。
