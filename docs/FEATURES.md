# tmd-cli 功能清单

> 需求变更验收总文档。按域分组,一行一个功能点,不做关联。

## 工作区会话

- 添加工作区(目录选择器),工作区即会话容器
- 工作区卡片:双态文件夹图标 + 名称 + Default badge
- 工作区 hover 动作组:切到主区 / 刷新会话(重扫磁盘历史) / 新建会话菜单
- 工作区右键菜单与「+」等效
- 工作区折叠/展开:单卡 toggle + 全部折叠/展开按钮,折叠态持久化
- 新建会话菜单:按 CLI 列出,portal + fixed 定位
- 会话模型:一个会话固定一个 CLI(profile + PTY + cwd + CLI 原生 session id),不可中途切换
- 会话恢复:由各 CLI profile 声明 resumeArgs,适配 CLI 自身会话存储
- 会话列表:活会话固定在所属 CLI 分组顶部,组内按时间倒序
- 磁盘历史:各 CLI 插件 listSessions 扫描,带相对时间
- 磁盘历史分页:初始条数 + 「更多」翻倍加载(默认 10 条起步)
- 会话时间轴:贯穿竖线 + 状态节点三态呼吸灯(绿=对话中 / 蓝=完成未读 / 灰=静止)
- 呼吸灯首写闸:用户首写前的输出(spawn 横幅/resume 回放/重绘)不亮灯、不结算未读
- 蓝色未读:组内置顶,点开查看即消
- 会话行右键菜单:复制 Session ID / 重命名 / 置顶 / 删除
- 会话重命名:应用侧覆盖层标题,不改 CLI 磁盘文件
- 置顶双作用域:置顶到全局 / 置顶到工作区内,当前作用域 ✓ 标记,点击迁移或取消
- 置顶投影:工作区置顶固定组顶不参与分页;全局置顶汇入侧栏顶部「已置顶」区
- 删除会话:两步确认(首击武装再击执行),物理删除磁盘 jsonl
- 会话列表显示预算:总数(1–100,默认 20)按 CLI 分组均分,已配额组按配额(显式 0 = 不露出)
- 预算弹窗:总数编辑行 + 每注册 CLI 一行配额;非法提交拒绝并回退;清空配额回均分;剪除已卸载 CLI 残留 key;修改即时生效
- 预算为独立可插拔插件 session-budget:经工作区标题行挂载点贡献入口,拔出回默认分页、重插恢复预算数值
- 活动守望:内核单点结算会话活动状态(对话中/完成未读/静止)
- PTY 生命周期:spawn / read / write / resize / kill,双线程聚合泵
- 会话输出落盘:64MB 旋转日志 + 幕布往前翻页读取
- 输出缓冲分块(上限可配)与字节流安全截断
- 近期会话:欢迎页展示磁盘最近会话,可快速进入

## 对话框(Composer)

- 富输入 textarea,发送快捷键可配置(Enter 发送/Shift+Enter 换行,或 ⌘/Ctrl+Enter 模式互换)
- 触发符 `@`:文件/文件夹引用,候选来自文件树
- 触发符 `/`:命令候选,由 CLI profile 声明,CLI 自己解析
- 触发符 `$`:技能候选,由 CLI profile 声明,不支持则不激活
- 触发下拉键盘导航:↑↓ 选择 / Enter / Tab / Esc,选中替换触发符 + token
- 发送编排:translate 钩子处理语法差异(如 `$skill` → `/skill:skill`),与手动输入同一发送路径,不拦截不解析
- 多行文本直发,CR 提交
- 图片拖入/粘贴:落盘临时文件 → 注册附件 → 输入框注入 `@path `
- 附件条:展示/删除/重排;删附件同步删 `@path` 文本,删文本同步移除附件
- 拖拽悬停视觉:accent 内环 + 虚线遮罩
- 只读状态工具栏:当前会话模型 + 思考强度,读各 CLI session JSONL,2 秒轮询,不可识别显示 `—`,不可交互
- Quota 额度 chip:composer 工具栏只读额度指示
- 额度查询:7 类供应商 HTTP 协议适配 + 未知中转站探测;codex/claude 官方 OAuth 优先本地快照零 HTTP;自定义 key 按 base_url 检测供应商
- 凭据引用:`$ENV_VAR` 只读解析,`!command` 拒绝执行
- 命令抽屉:⌘/Ctrl+K 开合,右上角开关按钮,Esc / 点击外部关闭,无活跃会话置灰
- 命令抽屉分区:命令 / 技能 / MCP / 插件,分区按声明派生,只渲染有数据的分区 + 「全部」聚合
- 命令抽屉过滤:实时过滤命中 name/description,打开时清空并聚焦
- 命令抽屉动作:send 直接发送(经 translate,toast 反馈并收起)/ insert 光标处插入(缺省),插件分区项点击切换对应面板
- 命令抽屉运行时发现:listSuggestions 声明优先,失败回退静态表,60s TTL 缓存
- 命令抽屉图标:候选可声明语义图标,未收录回退 kind glyph
- 消息锚点栏:composer 右缘用户消息 dash 导航,超长抽样分桶
- 锚点 hover 预览卡:序号 + 首行摘要;点击定位 xterm buffer 平滑滚动;active 逐帧追踪
- 发送事件:发送路径广播 prompt 事件(供审批线归批)

## 审批线

- Ask 等待确认检测:内核单点检测 PTY 输出中 CLI 阻塞等待确认的界面标记(跨分片 / 夹杂 ANSI 均可命中)
- 等待确认标签:会话列表行(含全局置顶区活会话)显示绿色胶囊,用户作答立即清除,会话消亡一并清理
- 重绘去重:同一未答提问反复出现不重复广播事件
- Ask 提示音:检测命中播放,每轮(以输出静默为界)最多一次,新一轮确认再次播放
- 提示音配置:设置页行为 tab,开关(默认开)+ 内置音效选择(默认/风铃/铃声/叮咚)+ 试听按钮,即时持久化
- 提示音设置兼容:非法值回落默认,旧配置无损加载
- 批次定义:一轮对话(相邻两条用户消息之间)的所有文件改动为一个批次
- 快照机制:影子对象库(裸仓库只写 blob/tree 不建 commit),只记变动集 + git XY 状态码 + baseOid,不碰用户仓库
- 锚点快照:用户消息发送时捕获,失败不阻塞发送,后台重试一次仍失败标 partial
- 改动归批:轮询 git status,增量路径归入进行中批次;无锚点数据退化为时间窗批次
- 批次状态机:open → pending → reverted / done;pending 唯一可回退
- 审批语义:通过 = 什么都不做,回退是唯一动作;与 git 插件零耦合
- 审批时间线面板(右栏):批次倒序,批次行 = 序号 + prompt 摘要 + 文件数 ±stats + 状态徽标 + 时间
- 文件行常驻展开,逐文件状态字母 chip;resume 断档线,断档前批次只读
- 点击批次/文件行 → 中央开批审阅单 tab(一批一个 tab,文件行深链滚动高亮)
- 批审阅单:用户消息全文卡 + AI 修改的文件分区(状态 chip + 路径 + ± + 着色 diff,默认展开可折叠)
- 回退整批 / 只回退此文件:回退前自动打恢复点(guard)
- 反悔:reverted 批可恢复回来,按回退路径定向恢复
- 回退冲突:文件被手改即跳过并显式列出,绝不静默覆盖
- 自动已处理:文件已提交或内容偏离批次后像 → 逐文件标记,全部失配批次自动转 done
- 陈旧标记:内容已变的文件行内标记,不可回退仍可看 diff
- 会话严格绑定:审批线生命周期 = 单个会话,新会话从零开始,其他会话批次不可见
- 快照清理:prune 命令按保留条数 + TTL 清理(设置页入口未接)
作者指出的设计点
- 审批线每个节点应该是一次对话的 ai 全部文件变更,包括新增,修改,删除.审批线的内容应要跟随 ai 输出落盘记录相当于账本.
- 审批线节点中的数据不应该和其他会话或者本会话其他轮次代码关联,应该是绝对独立的.应该存储副本,这样有利于文件回退和应用,恢复作为依据.这几个功能应该结合审批线里面存储的变更信息 加上git 一起作为功能实现的点,而不是光靠 git 这样不准.
- 最后审批线应该是独立的,相互不泄露,落盘的. 和工作区+会话+当前会话轮次 关联.支持审批,回退,恢复,等基础能力, 每个轮次保存的文件变更信息一定要是独立的. 这些信息和 git 工作区的最终变更是两套.
