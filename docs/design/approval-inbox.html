设计要点与边界

实施注记(2026-09-25):落地时本页的「同意(y)/拒绝(n)」预设代发键未实施 —— 各 CLI 键位语义不一(1/2/y/a/n/Esc),发错键 = 批错操作,沿用 M2 评审 A2 纪律(mobile 浮标同样只导航不代发);实际应答形态 = 自由文本(原样写入会话)+ 直达。落地记录:openspec/changes/2026-09-25-approval-inbox/。

  • 零新检测:数据源就是现有 askWatch 的 isWaitingConfirm;私有 askMarks 已按 CLI 声明,收件箱不感知 CLI 私有格式,只消费状态位与页脚摘录(摘录取自检测时已剥 ANSI 的页脚窗,不再二次读屏)。
  • 作答纪律:全部经 host.writeSession,作答即触发既有「写后抑制窗」(ASK_REARM_SUPPRESS_MS),残影重绘不会让卡片复燃。
  • 作答语义分型:y/n 型可一键;select 型给选项点选(序号由 askMarks 捕获的选项行生成);omp 自由问答只有预设短语 + 自定义输入,不猜选项序号。
  • 撤查与生命周期:已作答卡片保留 30s(置灰条展示所发文本),供发现发错时手动追回;会话移除/进程退出即清卡。
  • 不进收件箱的:SSH 会话(检测侧已跳过)、影子会话、已归档会话。
  • 落点预估:kernel 无改动(host 已暴露状态与写入口);右栏页签 + 收件箱组件一个插件;src/mobile/ 树加审批页,消费各 cli 插件 askMarks 声明(经 @plugins 别名,合规)。
