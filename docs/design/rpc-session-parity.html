决策落点(D1-D6 全部按推荐项落形,不另设问)对应规划 §4

D1 左栏形态 采用 a · 独立分区

b · 混入引擎分组活会话区
「带渲染的会话」独立小节与新建菜单三分区同构;行首 ✦ 图标与 PTY › 图标区分,守望语义(因果信号 = prompt ack/settled,而非字节流)互不污染。
→ 左栏中部蓝色组标小节;点击只激活中央 structured tab,不碰幕布 tab。

D2 数据通道 采用 a · kernel 投影

b · Rust 会话表统一(2026-09-30 已否决)
新 kernel 模块 structuredSessionTabs(仿 sessionViewTabs 先例,文件头声明双消费方:workspace 渲染 + structured-session 广播);Rust PTY 注册表零改动,行下注明数据来源。
→ 左栏行下灰字「数据 = kernel 投影 topic」;PTY 行数据来源不变。

D3 操作面 采用 最小集起步

跳转 + 关闭(最小集)→ 批次 5 补重命名 + 静音;置顶/归档/删除观望。
右键菜单四项即全量;静音用自有 localStorage 键,不接 sessionMutes(该服务按 PTY sessionId 键)。
→ 右键任一 RPC 行可见;PTY 行右键菜单不出现 RPC 项,反之亦然。

D4 审批进全局箱 采用 b · 不进

a · approval-inbox 增 RPC 卡
confirm 回路在 tab 内闭环(依赖回路上下文);全局箱按 PTY sessionId 键,虚拟 id 会污染。发现性由行黄灯补偿。
→ 状态机切到「等待审批」时行灯变黄 1s 呼吸;审批卡仍在中央 tab 内。

D5 reload 行为 采用 a · boot 重接

b · 维持 kill_all
枚举带 label 活流 → get_state + 磁盘种子重建 tab 与行;失败兜底 = kill 单流(与现状等价)。前提修正:现有 Rust 泵在 emit 失败(webview 失联)时 break 并 2s 后杀树——必须先加 adopt 标记改造,否则重接对象根本活不到 boot 枚举。
→ 点「模拟 webview reload」看重接 toast;恢复进度与 PTY SessionRestorePill 排队不混跑。

D6 单实例锁 采用 维持

放开(同 cwd 并行) — 引擎侧会话文件互踩未验证,不添变量。
tab id = structured:profileId:cwd 即锁;新建同键会话 → 激活既有 tab 而非新起。
→ 点「模拟新建 RPC 会话」:toast 提示「已激活既有会话」,不产生第二行。
