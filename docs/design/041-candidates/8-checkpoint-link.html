交互与实现说明

  • 映射键 = prompt 文本:账本 BatchInfo.prompt 与转录用户消息同源(都是发送原文),而 prompt 文本本身就是 jumpToAnchor 的 needle(24/14/8 字符梯队 + ≤12 页回溯,批注揭示/锚点栏同款)——两个既有数据面之间只差一个前端映射函数。
  • 方向 B 匹配口径:TimelinePanel 条目按 session_id + prompt 文本匹配 BatchInfo;同名 prompt 多轮按 seq 最近匹配;miss = chip 不渲染,不猜测。
  • 方向 A 复用检索增强的时序桥:已关会话 openDiskSession → 等 xterm handle → jumpToAnchor——与候选 5 是同一座桥,两候选共享实现。
  • 归因可信度不冒充:attribution="git"(推断模式)的轮次,变更集上沿用现有「git 归因」提示文案。
  • 边界如实:CliUserMessage 无时间戳(补时间戳要动 10 家适配器,既有注释明言二期)——本项用文本匹配绕开,不碰适配器。

已有底子:LedgerEntry/BatchInfo 账本结构(prompt/turn_files/attribution 全在)+ TimelinePanel(messageAnchors 订阅 + miss 闪烁语义)+ jumpToAnchor needle 梯队 + CheckpointsPanel 批次行。成本:低-中(纯前端映射 + 两个面板各一组 chip/按钮)。风险:CLI 规范化/截断 prompt 致 needle miss(降级 = 不渲染/闪烁);同名 prompt 多轮(seq 最近匹配)。验证:真实仓库跑 3 轮会话,双向跳转各 3 次 + git 归因轮提示正确。
