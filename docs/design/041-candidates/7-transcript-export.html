交互与实现说明

  • 缺口是实证的:viewer 目录 grep copy/export/save 无业务命中;structured-session、wiki、docgen 也无会话级导出路径——九家 profile 的 readSessionTranscript 是当前唯一没有消费出口的全量数据面。
  • 导出三件套照抄 docgen:pickSavePath(保存对话框原语现成)→ writeText(原子写)→ toast;Windows 保留设备名(CON/PRN…)加尾下划线的 sanitize 一并照抄。
  • blocksToMarkdown 是纯函数:CliTranscriptBlock {id, role, text, images?, startedAt?, tool?} → md 字符串,可 node 直测,不碰 UI。
  • 入口两处:会话查看 tab 工具行首版;活会话 liveOverlay(1s 探测增量面)后补同一按钮,数据同源。
  • 角色映射是方案取舍(要大仙过目):工具折叠一行 / thinking 丢弃计数 / 图片首版丢弃计数 / 截断头部标注——每一项都标注了理由与升级路径。

已有底子:九家 readSessionTranscript 声明 + CliTranscriptBlock 块结构 + viewerTab 分批渲染 + pickSavePath/writeText 原语 + docgen 导出样板(含 Windows 文件名 sanitize)。成本:低(纯前端零 Rust)。风险:角色映射取舍(页面已列,拍板即实现);长会话 md 体积(块级截断已控)。验证:omp/claude 各导一条,md 结构与 viewer 一致性目检;Windows 文件名用例照抄 docgen。
