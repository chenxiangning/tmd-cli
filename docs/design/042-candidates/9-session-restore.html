交互与实现说明

  • 持久三段身份,不持久 tmd id。sessionTabs.ts:15 头注明示「PTY 会话不跨应用重启存活,持久化只能恢复死 id」,现存 ids 即 tmd PTY id(:34);本项正面推翻该前提。key = sessionOverlayKey 三段 wsId:profileId:cliSessionId,拼法先例 SessionTabBar.tsx:65-68;resume 换壳后 PTY id 变、三段不变 —— 活会话按 cli 身份反查先例 anchorJump.ts:123-129 findLiveSessionId。
  • 恢复走磁盘回放,不走冻结快照。重启后内存 outputBuffers / screenMirror 全丢,terminalFreeze.ts:9-10 明示重开磁盘会话「存档天然不命中」;open() 自带 prefetchDiskTail 磁盘先行回放(sessionSpawn.ts:155;diskReplay.ts:25,512 KiB 尾窗),回位即见历史尾帧。
  • 恢复链 = host.openDiskSession(profileId, root, wsId, cliSessionId),与侧栏点击同一通道(SessionList.tsx:104-107);在途去重、聚焦、标题回喂(noteSessionTabTitle)全部白得,不新造第二通道。
  • 串行原因:每次 resume 是一次 spawn 重操作(开 PTY + 磁盘尾取回放),多路并发会叠加首屏压力;串行 + pill N/M 进度可感知,跳过钮随时终止剩余 key。
  • 与保留律竞态:启动补扫同在 45s 错峰(BOOT_SWEEP_DELAY_MS),两条 45s 链先后不确定 —— 恢复器在每个 key resume 前先做存在性检查(失败矩阵第 1 行),不恢复刚被清扫的会话。
  • tile 平铺零新逻辑:平铺按打开集合渲染(MainPanel,容量即保活上限),恢复出 N 个 tab 且 tile 开时自然并排;容量挤除与会话消失的收敛照旧生效。

已有底子:openDiskSession 通道 + hygiene 45s 错峰先例 + 三段 key 惯例(置顶/归档/删除/保留四层同构)+ settings 三源。成本:M。风险:串行恢复拖慢首屏(45s 错峰 + 可跳过缓解);claude fork 会话可能漂移 key 导致恢复落空([INFERENCE] 边界,失败矩阵「spawn 失败·保留 key」兜底)。验证:失败矩阵五路径各一测试 + 真机重启目检(开 4 会话重启,核对回位/跳过行态与 pill 收起)。
