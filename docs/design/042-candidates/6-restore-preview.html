快照信息轮次 + 时间 + 批次构成 + 引擎 pill;引擎名取大仙真实名单(omp/claude/codex/kimi/grok/qoder/dsh)

行数摘要每文件 +/-N 行;binary 文件按 0/0 行计;只出摘要清单,不渲染全 patch(300 行铁则)
截断默认显示前 6 行 + 「共 N 文件」计数;点展开补齐摘要行,不展开 patch

「撤销应用」(review.rs:35)与恢复走同一预览组件;撤销复用该批恢复时的预览数据,不新发 dry-run——guard 信息=回退前一刻工作区,增量≈0,且省一条 IPC。被否单独 dry-run:guard 无 per-path plan 结构,要新造。

设置口径

零新键预览是信息增强不是门槛——checkpoints 设置分区不加任何行为开关
截断常量预览默认显示前 6 行为常量(非用户可调),超出折叠进「共 N 文件」展开

行为边界与明确不做

  • 行为边界:预览为只读 plan_restore 计算(账本 before/after oid + live 一次读),不落盘、不改 ledger;弹层出现与武装确认之间不刷新预览(窗口内冻结,执行时 restore_batch 以最新 live 重新判定,skip 兜底安全)。
  • 行为边界:「覆盖本地」判定 = 账本 untouched/surgical 判定(surgical 擦除行),不用 git status 交集——git 会把会话自己刚写的未提交改动全员误标,恐吓化;归因只到文件粒度,不猜行级冲突。
  • 行为边界:预览失败路径必须可降级—— dry-run 是信息增强,永远不是恢复的门槛。
  • 明确不做:审批卡语义不变——确认弹层仍是两步武装确认(3s 回弹),只做信息升级,不引入二次审批或多步向导。
  • 明确不做:不渲染全 patch;不做逐 hunk 勾选、不提供「只恢复部分文件」的选择性恢复。
  • 明确不做:不做 checkpoint 浏览大改——预览挂在既有确认弹层位置,不新增独立页面/标签页。
