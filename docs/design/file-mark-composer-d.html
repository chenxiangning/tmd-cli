数据契约 · 0 容忍红线:源文件零写入

存放点(全局唯一)工作区级 sidecar:.tmd/marks.json(不进 git,已加 .gitignore 建议);内存态 = 全局 store,文件打开/切换/关闭都不丢。源文件从头到尾不被写、不被改 buffer、不加任何隐藏字符。
锚点结构{ id, path, startLine, endLine, headTail 指纹(首行+尾行内容 hash), note, state, createdAt } —— 行号是显示值,指纹是定位置信源。
重定位文件变更后按指纹在 ±N 行窗口内模糊重定位;命中 → 静默更新行号(面板标「漂移已重定位」);不命中 → 标「失联」,绝不瞎指到错误行,由人决定删除或重新圈选。
渲染层锚点走文件视图的装饰层(与 gitDecorate 同通道,纯 overlay);文件关闭 → 装饰卸载,sidecar 保留;重开 → 按指纹复锚。
发送语义发送 = 把「path:行号 + 摘录原文快照 + 备注」序列化进 composer 引用;AI 拿到的是快照文本,即使之后文件改了,AI 看到的仍是标记时的内容,可复现。
回链终端输出里 path:line 模式识别为回链(纯幕布外增强,不动 PTY 字节);点击 → 查全局 store → 激活文件 tab → 按指纹定位 → 闪烁锚点。

方案 D 取舍(相对 A/B/C)

从 A 继承行间锚点的所见即所得:书写、查看、发送状态都在代码旁;新增默认折叠态,解决 A 标记多挤视野的唯一硬伤。
从 B 继承右栏全局中心:跨文件聚合、勾选批量、按文件分组发送;解决 A「单文件操作」的核心缺口。
从 C 继承composer 芯片与既有附件体系同构;AI 回链不依赖文件侧对象,按 path:line + 指纹定位。
新增红线sidecar 存储 + 内容指纹锚定,源文件零写入;漂移可感知、失联不瞎指。
代价两套界面(行间 + 面板)状态要实时同源;指纹重定位需要一次文件监听与 ±N 行扫描(代价可忽略,单文件 KB 级)。
