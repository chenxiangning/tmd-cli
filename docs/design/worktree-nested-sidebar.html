方案 A — 侧栏工作区分层树:worktree 是仓库的子节点

理解:一个仓库的并行工作线不该是平铺的 N 个工作区,而是 父节点(主仓)→ 子节点(各 worktree) 的从属关系;展开即管理,点击即切换。

交互要点
  • 识别规则:侧栏工作区按「同一仓库」归组 —— 主仓为父,其 worktree(git worktree list 反查)自动挂为子节点,不再各自平铺占行。
  • 子节点行 = 分支名(wt/ 前缀高亮)+ 脏净点(未提交文件数)+ ahead/behind + 该树下运行中的会话数徽章。
  • 点击子节点 = 切换到该 worktree 工作区(会话、Git 面板、文件树整体跟随);hover 浮出「终端 / 移除」。
  • 「N 棵树」计数与折叠态让多仓侧栏不膨胀;主仓行恒在顶部,worktree 不会喧宾夺主。
  • 归组失效兜底:worktree 被外部删除 → 子节点变灰标「悬空」,一键清理(走 prune)。
落地面

侧栏工作区列表(app-shell 侧栏)加「仓库分组」渲染层;git_worktree_list 已有,补一个 worktree→workspace 反查即可。改动收敛在工作区列表组件与 kernel/workspace 归组逻辑,不动 PTY 与会话生命周期。
