设计要点与边界

  • 零新采集:editWatch 已按会话入账改动路径(record_edit 终审过),checkpoints 账本已有时间戳;雷达只是把两表按「工作区 + 文件 + 时间窗」join,新增的是聚合查询与一个右栏面板,不动采集链。
  • 判定语义:同工作区、双方均为活会话、判定窗(默认 10 分钟,可配)内都写过同一文件才成组;时间轴红带标出交叠段,一眼看出谁先谁后。
  • 只预警不拦截:不做文件锁、不阻塞 PTY 写入——两个 agent 改同一文件不同区域是合法并行,拦截误伤远大于收益;裁决权在人。
  • 出口:跳转会话(高亮侧栏行)、双栏 diff 复用 git 面板既有视图;忽略名单落 settings.conflictRadar.ignore(按文件,24h 生效)。
  • 解除与沉淀:一方归档/退出即自动解除,组沉底保留 1 小时供回看;组内 mini diff 与统计来自 checkpoints 锚点,非重新读盘。
  • 落点预估:join 聚合放 src/plugins/conflict-radar/(消费 editWatch/checkpoints 既有账本,经 ctx 注册面订阅);侧栏会话行加冲突徽标 = 侧栏一处小改;kernel 零改动。
