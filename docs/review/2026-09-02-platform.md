# 跨平台兼容性评审(win / mac / linux)

范围:`src/**` 全部 TS/TSX + `src-tauri/src/*.rs` + `tauri.conf.json` + `capabilities/default.json`。
格式:`文件:行号 | 严重度 | 问题 | 建议修法`

## 结论总览

| 平台 | 高 | 中 | 低 |
|---|---|---|---|
| Windows | 3(路径分隔符三连) | 3(slug 规则 / cwd 大小写匹配 / UA 无兜底) | 2 |
| macOS | 0 | 1(TERM 缺失) | 1 |
| Linux | 0 | 0 | 2(字体、UA 分支) |

窗口控制链路(macOS overlay / Windows decorations=false+自绘按钮 / Linux 原生装饰)架构上是对的;
Rust 侧 fs.rs/session.rs/quota.rs 全部使用 `PathBuf::join` 与 `dirs::home_dir`,路径处理合格。
真正的系统性缺口在 **TS 侧的路径字符串处理**:一半消费点用 `split(/[\\/]/)`,另一半只认 `/`。

## 高危(确定性 bug)

### 1. `src/app-shell/RightPanelToolbar.tsx:68 | 高 | 正则笔误只切 "/"
```ts
const seg = root.split(/[\/]/).filter(Boolean).pop();
```
`[\/]` 字符类里只有一个转义后的 `/`,并不含 `\`(对比同仓库正确写法 `contributions.tsx:17` 的 `[\\/]`、`AppShell.tsx:95` 的 `[\\/]`)。
Windows 下 workspace root 为 `C:\Users\x\proj`,split 不产生任何切分,`deriveWorkspaceLabel`
返回整串路径大写后塞进顶栏 section title。
**修法**:`root.split(/[\\/]/)`。

### 2. `src/kernel/workspace.ts:86 | 高 | workspace 名只按 "/" 切
```ts
const name = root.split("/").filter(Boolean).pop() ?? root;
```
Windows 下 `addWorkspace("C:\\Users\\x\\proj")` 得到的 name 是完整路径
`C:\Users\x\proj`,持久化进 workspaces.json 后所有展示位(侧栏/面包屑)都是长串。
**修法**:`root.split(/[\\/]/)`,与 AppShell.tsx:95 对齐。

### 3. `src/plugins/files/index.tsx:29 | 高 | 文件 tab 标题只按 "/" 切
```ts
title: path.split("/").pop() ?? path,
```
`path` 来自 Rust `fs::list_dir` 的 `entry.path().to_string_lossy()`,Windows 上是反斜杠路径
→ tab 标题 = 完整绝对路径。
**修法**:`path.split(/[\\/]/).pop()`。

## 中危(真实风险)

### 4. `src/plugins/cli-pi/index.tsx:40 | 中 | pi slug 规则不含 Windows 路径形态
```ts
const slug = `--${cwd.replace(/^\/+/, "").replace(/\//g, "-")}--`;
```
Windows 的 cwd 是 `C:\Users\x\proj`(盘符冒号 + 反斜杠),该代码只去前导 `/`、只替换 `/`,
生成的 slug 形如 `--C:\Users\x\proj--`(含非法文件名字符 `:`),与 pi CLI 在 Windows 上真实落盘的
slug 目录不可能一致 → `listSessions`/`readSessionStatus` 永远扫空目录,Windows 下历史会话列表恒为空。
`src/plugins/cli-omp/index.tsx:46-50` 的 omp slug(`cwd.startsWith(home)` + 只替换 `/`)同病。
**修法**:先统一归一化(把 `\` 视为 `/`、剥离盘符),再实证 pi/omp 在 Windows 的真实 slug 规则后对齐;
至少补 `replace(/[\\/]/g, "-")` 与盘符处理。

### 5. `src/plugins/cli-codex/index.tsx:63 | 中 | cwd 匹配为严格字符串相等
```ts
if (!meta || meta.cwd !== cwd) continue;
```
`meta.cwd` 来自 codex rollout 的 session_meta,`cwd` 来自工作区 root。
macOS 默认 APFS 大小写不敏感、Windows NTFS 大小写不敏感且分隔符混用(`/` vs `\`),
同一目录的两种写法会被判为不同 → 历史会话漏配;`readCodexSessionStatus`(同文件 :86)同。
**修法**:比较前做归一化(统一分隔符 + 按平台决定是否 toLowerCase),或在 mac/win 上
一律 case-insensitive + 分隔符归一后比较。

### 6. `src/kernel/platform.ts:1-24 + src-tauri/src/lib.rs:176-180 | 中 | UA 探测无兜底,Windows 探测失败 = 窗口无法关闭
platform.ts 头注释声称"用 navigator.userAgent 判断 + tauri 兜底",但代码里**没有任何 tauri 兜底**
(没有 `@tauri-apps/plugin-os` / `type()` 回退)。探测失败返回 `"unknown"`,而消费方
`AppShell.tsx:221` 是 `if (platform !== "windows") return null;`。
Windows 上窗口是 `decorations(false)`(lib.rs `#[cfg(target_os = "windows")]`),
一旦 UA 探测异常 → 自绘关闭/最小化/最大化按钮全部不渲染 → 用户只剩 Alt+F4。
**修法**:UA 失败时用 `plugin-os` 的 `type()` 兜底,或把 unknown 并入 windows 分支
(自绘按钮比没按钮安全);同时删/改注释使其与实现一致。

### 7. `src-tauri/src/pty.rs:68-73 | 中 | spawn 不设 TERM/COLORTERM,macOS .app 下 TUI 退化
```rust
let mut cmd = CommandBuilder::new(&spec.command);
cmd.args(&spec.args);
```
portable-pty 的 `CommandBuilder::new` 只继承宿主进程环境(`get_base_env()`)。
macOS 从 Finder/Dock 启动 .app 时环境**没有 TERM**(launchd 环境),Windows ConPTY 同理无 TERM 语义。
omp/pi/codex 这类全屏 TUI 在 `$TERM` 缺失时会按 dumb terminal 渲染或报错。
**修法**:spawn 前 `cmd.env("TERM", "xterm-256color")`(unix)并考虑 `COLORTERM=truecolor`。

## 低危(建议)

8. `src/plugins/cli-pi/quota.ts:113 | 低 | `piAgentDir()` 对 `PI_CODING_AGENT_DIR` 只做
   `replace(/\/+$/, "")`,Windows 风格的尾部 `\` 不剥离;且全项目 TS 侧用模板串拼路径
   (`${home}/.codex/sessions` 等,cli-codex/index.tsx:58、codexLocal.ts:136、cli-omp/index.tsx:51),
   Windows 上产生 `C:\Users\x/.codex/sessions` 混合分隔符——Rust fs 能容忍,但日志/调试体验差。
   建议 ipc 层加一个 `joinPath` 原语或前端统一 `replace(/[\\/]/g, …)` 归一。

9. `src/plugins/cli-omp/index.tsx:47 | 低 | `cwd.startsWith(home)` 无路径边界:
   `/Users/foo2/x` 会被判定在 home `/Users/foo` 之下,slug 算错(全平台存在,
   Windows 大小写差异进一步放大)。建议 `cwd === home || cwd.startsWith(home + sep)`。

10. `src/kernel/TerminalView.tsx:37 | 低 | `fontFamily: "Menlo, Monaco, 'Courier New', monospace"`
    未按平台区分:Linux 落 `monospace`(无连字/CJK 宽度依发行版),Windows 落 Courier New。
    建议按 platform 给字体栈(如 Windows 加 `Cascadia Mono, Consolas`)。

11. `src-tauri/src/pty.rs:190-204 | 低 | `random_u64` 读 `/dev/urandom`,Windows 必走
    `pid ^ nanos` 兜底(可预测)。会话 id 非安全用途,可接受;若要统一,改用 `getrandom` crate。

12. `src-tauri/src/lib.rs:166-181 + src/app-shell/AppShell.tsx:219-239 | 低 | Windows 自绘窗口
    控制区缺 Win11 snap layouts(hover 最大化按钮弹布局浮层)与双击 titlebar 切换最大化;
    非缺陷,属平台体验差距。capability 侧 `allow-minimize/allow-toggle-maximize/allow-close/
    allow-start-dragging` 已齐备,无权限缺口。

## 已核验无问题项(排除项)

- **平台探测覆盖面**:UA 三分支(mac os x / windows / linux)+ unknown,覆盖三平台;
  WebKitGTK/Chromium webview 的 UA 稳定含上述标记。
- **窗口控制分支完备性**:macOS=Overlay+hidden_title+70px inset(titlebar.css:36);
  Windows=decorations(false)+自绘三键(AppShell.tsx:219);Linux=原生装饰(lib.rs 不 cfg)→
  WindowControls 返回 null 是**正确**的,Linux 有系统标题栏。
- **Rust 路径**:fs.rs/session.rs/quota.rs 全部 `PathBuf::join` / `dirs::home_dir()`(session.rs:53-70),
  无字符串拼接、无家目录硬编码;`/dev/urandom` 有兜底。
- **shell/PTY**:无 shell 探测需求(直接 spawn CLI 本体);portable-pty 0.9 在 Windows 走 ConPTY、
  `search_path` 支持 PATHEXT(npm 的 `pi.cmd`/`codex.cmd` shim 可被 CreateProcessW 经批处理通道启动);
  kill/write/resize 走 portable-pty 抽象,跨平台一致。
- **快捷键**:全仓库键盘处理只有 Escape/Enter/Tab/方向键/Space(grep 全量确认),
  无 Cmd/Ctrl 修饰键假设。
- **换行符**:JSONL 解析处(`sessionStatus.ts:26`、`codexLocal.ts:82`、`cli-codex/index.tsx:41`)
  `split("\n")` 后均 `trim()` 或 `JSON.parse`,`\r` 被 JSON 空白规则容忍,CRLF 安全。
- **capabilities/default.json**:窗口控制所需四项权限齐备,无缺失。
