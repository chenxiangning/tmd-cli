# 后台「等待确认」不可见 / 前台迟滞 / 改窗口尺寸即消失:镜像几何失真评审与 v3.2 修复

- 日期:2026-09-29
- 状态:已完成(修复在工作树,未提交)

## 症状(用户报告)

1. 后台运行(tab 未打开)的会话阻塞在 Ask 确认时,侧栏行「等待确认」徽章不出现;
2. 前台(tab 打开)能看到但慢(秒级体感);
3. 稍微改变客户端窗口大小/位置,已亮的徽章就消失。

## 根因:v3.1 镜像两处几何失真(真实日志回放实证)

2026-09-11 的后台镜像修复(v3.1)参数从未与真实环境对齐,2026-09-29 取本机真实 PTY
日志(2.7MB 含已答面板 + 1.9MB 活会话日志)网格化回放实证:

1. **栅格不符**:镜像固定 80×24,而 Rust 侧 PTY spawn 默认是 **120×32**
   (`pty.rs default_cols/default_rows`)——头注「与 Rust 侧默认一致」是错的,
   从未一致过。TUI 字节按真实栅格排版,镜像按 80 列解释,长选项面板(CJK 折行)
   整帧错位。
2. **采样窗过浅**:镜像只采底部 8 行;前台探针 2026-09-27 已因「8 行够不着标记」
   真机根因加深到 24 行,镜像未同步——同一根因只修了一个通道。实测高面板的标记
   落在**距屏底 14-38 行**,旧参数(80×24 + 底 8 行)在全栅格网格(80-240 列 ×
   24-56 行)下**零命中**:后台等待结构性不可见(症状 1)。
3. **假缺席误摘**:前台 fit 过的会话回后台后,PTY 已是真实尺寸而镜像仍 80×24,
   SIGWINCH 整帧重绘在镜像里解释成垃圾屏 → 屏幕通道报「缺席」→
   `onScreenSample` 对称防抖把**字节通道已置位的等待也摘掉**(症状 3;关 tab
   转后台同理)。9-11 评审「不接 resizeSession 属过度设计」的权衡被实测证伪。
4. **前台底窗同样够不着大窗面板**(二次复查补):前台探针贴底采固定底部 24 行,
   而 omp 大窗布局面板在中上部、底部留空——窗口改大 → fit 行数增多 → 面板
   距屏底 30-38 行 → 前台采样假缺席 → 徽章被摘(症状 3 的前台侧机制;且后台
   镜像亮、点开会话让位前台窄窗反而灭,两通道口径不一致)。
5. **迟滞**:置位延迟 ≈ ASK_CONFIRM_MS(1.2s)+ 采样间隔。镜像/前台探针/守望
   计时器全按 1Hz 走,实测 2-3s 才亮标(症状 2)。

## 修复:askWatch v3.2

- **几何真源**(`askScreenMirror.ts`):懒建默认 120×32(对齐 Rust spawn);
  首建时拉 `session_size`(kernel/ipc 新增 `sessionSize` 绑定;webview 重载后
  唯一幸存的尺寸真源);`host.resizeSession`(唯一尺寸入口)中继给镜像——前台
  fit 过的会话回后台后,后续整帧重绘按新栅格解释。在途拉取与中继竞态用几何代数
  闸仲裁(中继胜)。
- **全屏采样**:scrollback=0 的镜像缓冲就是物理屏,底部 8 行窗改为整屏上报——
  屏上有标记即可观测,滚出即消失无历史假阳性,瞬态闪帧仍由 ASK_CONFIRM_MS
  持续在场防抖过滤(对栅格残差也不再有敏感性)。
- **节拍 250ms**:镜像采样、前台探针、守望计时器三处 1Hz → 250ms;置位延迟
  降到 ≈1.2-1.45s(实测回放 1.50s 含分片写入),判定阈值(1.2s 确认窗 / 8s
  写后抑制 / 2s 自愈静默)一概未动,防抖语义不变。
- **前台探针同口径**(二次复查补):TerminalView askProbe 贴底时改采**整个视口**
  (与镜像全屏同窗),废弃底部 24 行固定窗——大窗高面板前后台一致可见,
  幕布挂载/卸载的通道切换不再产生置位差异;上翻停采闸原样保留。
- **backfill 先等几何**:readopt 磁盘尾补底改异步,等 `session_size` 拉取定稿
  再回放整帧(错栅格解释的补底是垃圾屏);回放途中会话移除不写。
- **顺手修真 bug 两处**:`AskWatch.onSessionRemoved/resetForTest` 补清
  `marksBySession`——同 id 重建原会继承上一代 CLI 私有标记(旧 1Hz tick 下
  升级不及掩盖;250ms tick 下被 askWatchCore.test 的既有契约用例当场暴露);
  `AskScreenMirror.remove` 无条件清 `pendingSize`(未 feed 会话的 resize 中继
  条目原会随会话消亡泄漏)。

## 验证

- 真实日志端到端回放(一次性探针,验后即删):1.9MB 真会话日志按 8KB 分片喂
  真链路(镜像 → AskWatchFeed.onScreenSample)。旧参数(80×24 + 底 8 行)
  `present=false`(症状 1 复现);新参数默认 120×32 / 200×48 / 184×40 三种
  几何均 **1.50s 置位**(≈6 个采样 tick)。
- 单测:askScreenMirror 契约重写(几何真源四态:默认/中继先至/已建中继/拉取
  回包与竞态;全屏采样;backfill 就绪序与途中移除;pendingSize 清理),
  askWatch 双文件计时断言对齐 250ms tick 网格(`pastConfirm` 1300→1200,
  落网格间隙,复现路径语义原样);host 链路补 resize 中继大窗用例
  (标记距屏底 >24 行,漏中继或固定底窗即失败)。
- 全量 `pnpm typecheck / test(410 文件 3237 用例)/ check:arch-boundary /
  check:file-size / build` 绿。
- 待真机 `pnpm tauri:dev` 目检:后台挂起 → 徽章 ~1.5s 亮;改窗口尺寸 → 不消失;
  作答 → 即清(留大仙)。

## 残余权衡

- 全屏采样的误报面:屏上 transcript 历史文本若含标记字面量(如讨论 ask 检测的
  会话回显 "Other (type your own)")且 CLI 静默,静态在场防抖可能假置位。
  底部 24 行窗时代同类型风险已存在(回显贴底),非新增类型;逃生通道:点开该
  会话 → 真实幕布接管采样 → 标记不在真实屏 → 缺席防抖 1.2-2.4s 自愈摘除。
- 镜像栅格滞后一个拉取往返(会话首字节至 `session_size` 回包间按默认栅格解释,
  数十毫秒窗):面板帧是整帧重绘,下一次重绘自愈,实测无感。
- 窗口完全遮挡/最小化时 WKWebView 节流 DOM 定时器,检测与系统通知边沿推迟到
  复见为止;失焦但窗口可见(macOS cmd-tab 常态)不受影响。App Nap 级抑制未处理。
- 字节通道(1024B 尾窗 + 末 5 行页脚窗)原样保留:claude 等纯文本流确认句式
  仍靠它,TUI 系 CLI 以屏幕通道为主路径。
