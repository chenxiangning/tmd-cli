# 客户端整体细节打磨(A+B)实施评审

> 日期:2026-11-03 · 状态:代码与自动化验证已收口,真实窗口逐项交互待用户验收
> 范围:便签、MCP 安装、CLI 配置、Relay/Retry、Web 访问、侧栏文件菜单及其直接触达面;不含其他 0.4.8 未提交改动。

## 1. 落地结论

- **便签:** 取消按钮与 Esc 共用脏稿确认;文本/图片使用事件时最新 ref;连续贴图基于最新图片集追加。编辑代次在取消、重进、保存开始和卸载时失效旧贴图,保存快照不会被在途贴图污染。StrictMode 重跑 effect 时正确恢复存活态。
- **MCP 安装:** 成功后 1.5 秒延迟关闭收进 effect cleanup,提前关闭或卸载后旧计时器不会再触发。
- **CLI 配置:** 写盘以同步 ref 单飞;旧实例异步完成后不再 setState 或上报 dirty。GUI 保存中禁用字段,raw 使用既有 CodeMirror readOnly;成功后以 `engine.load(nextRaw)` 的规范化值同步表单并清脏。toast 单飞计时器可复位、可清理,失败仍保留持久错误条。保存条和错误区补窄屏换行与长文本断行。
- **Relay/Retry:** Esc、取消和遮罩统一走 busy 关闭闸,成功路径仍直接关闭;编辑区与相关动作在 busy 时禁用。卡片补视口最大宽高、纵向滚动和动作区换行,错误与忙态补 ARIA。
- **Web 访问:** 刷新失败清旧地址;刷新按代次忽略旧响应,地址更新会作废旧复制反馈。复制失败进入错误区,成功才显示状态;连续复制以最后一次为准,计时器带身份复核并在卸载清理。
- **文件菜单:** 接入栈顶 Esc 关闭,打开聚焦首项,菜单按钮补 `role=menuitem`;既有鼠标路径不变。

## 2. Review 发现与处置

| 维度 | 当轮发现 | 处置 |
| --- | --- | --- |
| 正确性 | 保存开始后在途贴图仍可进入未包含它的保存快照 | 保存起点递增编辑代次,旧贴图立即失效 |
| 正确性 | 贴图回写与取消发生在同一渲染窗口时,旧 render 的 dirty 可能绕过确认 | 取消判定改读事件时最新 text/images ref |
| 稳定性 | Web 多次刷新可能乱序,旧失败可清掉新状态;旧复制结果可误标新地址 | refresh/copy 分设代次闸,刷新成功或失败都作废旧复制 |
| 稳定性 | 极端计时器时序下,旧 toast/copied 回调可能清掉新反馈 | 回调执行前复核当前 timer 身份;卸载统一 cleanup |
| 兼容性 | 配置长错误与保存动作在窄面板可能溢出 | 复用现有样式补 flex-wrap、max-width、overflow-wrap,不引入新组件或依赖 |
| 性能 | 异步治理是否引入轮询或常驻任务 | 未新增轮询;仅操作期 Promise、ref 与既有计时器,贴图合并为既有数组规模内一次 O(n) 追加 |

复核后未发现本批剩余 P0/P1 代码问题。没有新增依赖、IPC、全局状态框架或架构越界;没有修改版本号。
