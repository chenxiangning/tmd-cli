## 留观(发现不修,含理由)

- **桌面直连不做 pong 死线(relay 有)**:曾照 relay_agent 实现后撤回——ws.rs select 会阻塞在 socket 写(relay 写经 channel 不阻塞),且手机在途大帧会把 pong 排在帧后(TCP 串行),「入站静默 = 死」无法区分「对端消失」与「对端上传中」,误杀恰复发本批要治的病;僵尸线代价(分钟级 TCP 超时)小于误杀。需入站字节级活性观测才可安全启用。
- **useComposerSize 双击判定**(两次 pointerdown <300ms 即回紧凑):「拖一下松手立刻再抓精调」会被误判;v0.2.8 原样保真回归代码,要修应改 pointerup 位移阈值判 tap,留大仙拍板。
- **SheetBase 标题行/✕ 随长内容滚走**:建议 sticky,但属 UI 行为改动须真机目检(AGENTS 验证铁则),本轮不动。
- **WsTunnel pong 已到后 10s 超时 block 空转**(settled 挡业务):每 15s 一拍无泄漏,不值得加取消链。
- **relay 服务端 MAX_STREAM_FROM_PHONE=32MB 单流总量限**:拍照/选图帧 1.6~3.6MB/张,同连接连传 ~9-20 张触发拆流;属 deploy 侧策略(滥用权衡),建议按帧预算放宽或大帧免计,不在本批改。
- **endMsg 权威解析缺 event.id 恒空**(一轮留观项维持):行为等效,真要启用需 omp 真机帧序实证。
- **shellInvoke 无超时**:Swift reply 丢失(webview nil 时 evaluateJavaScript 静默 no-op)会挂 busy;但 pickImage/takePhoto 合法耗时是分钟级(用户慢慢挑照片),一刀切超时会误杀——要做得按方法分档,留大仙拍板。single-flight 闸已把最常见挂源(二次覆盖)堵掉。
- **clearShots(paths)/SpawnSheet 回填零直接测试**:仓库无 hook 渲染测试基建(全 node 环境纯函数/静态渲染),为本 effect 引 jsdom 不值;行为由 canSend 真值表 + 调用点逻辑间接覆盖,记缺口。
- **\b 与 \t 在 pending 态与 xterm 差一列**(三轮 xterm 对照顺带发现,先于本批):极边角,修需引入「pending 列位」概念,性价比低。
- **invoke 无幂等键,响应丢失型失败重试会双发**(at-least-once 固有):桥层加幂等序号是大改,文档化即可——发送失败条已保留草稿供人工判断。

pickImage single-flight 原留观项已在三轮落地(#22),不再留观。
